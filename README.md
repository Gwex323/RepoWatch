# RepoWatch

单用户、本地运行的多 Agent 工作台。第一阶段已实现 OpenAI Agents SDK 的真实
handoff、人工复现关卡、持久化状态与跨进程恢复。

## 当前范围

- Python + OpenAI Agents SDK 0.23.1，注册六个角色。
- FastAPI + SQLite 后台，React + TypeScript WebUI。
- 本地管理密码、会话校验、同源限制与 CSRF 校验。
- 系统发现样例：发现分页问题，人工操作复现，确认后恢复 SDK 执行。
- 已有 Issue 样例：自动验证后直接进入修复与审查，不要求人工复现，不重复生成 Issue。
- 可查看交接记录、预定义样例补丁、五项样例断言和本地 Issue/PR 草稿。
- 任务状态保存在数据库中；重启后可以继续等待确认或恢复已确认任务。
- 共享仓库记忆：按仓库和代码版本隔离，包含手工知识、复现记录及样例修复经验。
- 可登记 GitHub 仓库链接，下载固定提交的源码，并在本机 Docker 中安装、测试与运行。
- 可在运行配置中连接多个 GitHub 账号，校验身份、切换当前账号、更新令牌和解绑。
- 可检查已登记仓库是否能被指定账号的令牌读取；不会把读取成功当作写入授权。
- 测试或启动结束后自动排队分析源码与执行结果，保存疑似问题、代码依据和复现步骤。
- 可在 WebUI 配置仓库分析模型；未配置时任务等待，启用后自动继续。

**样例流程使用确定性的测试响应，默认不调用外部 LLM。** SDK 的 Agent、Runner、
handoff、审批中断和恢复是实际执行的；样例问题及补丁是预先定义的。
真实仓库分析和环境故障诊断可单独启用真实模型，见下方配置。
真实仓库的修复与发布尚未接入。

以下能力尚未启用：自主修复真实项目、
真实 GitHub Issue 接入、GitHub Fork/Issue/PR 发布、每日调度。
任何自动合并操作均不在系统权限内。

## GitHub 账号连接

进入“运行配置 → GitHub 账号 → 连接账号”，填写 GitHub 用户名和该账号的
Personal Access Token，点击“验证并连接”。页面提供 GitHub 令牌管理入口。
这里只校验 GitHub 身份和仓库读取，不要求预先授予发布或合并权限。

- 后台向 GitHub 请求真实身份；用户名不匹配时不保存，首次连接不自动导入 `gh` 登录。
- 可以保存多个账号，同时选择一个当前账号。切换前重新校验，失败保留原有选择。
- “更新令牌”用于授权过期、撤销或更换令牌；提交后输入框立即清空。
- “检查访问”只验证所选已登记仓库可读取，写入权限明确显示“未核验”。
- 细粒度令牌未返回传统权限范围时显示“GitHub 未返回”，不推断它拥有全部权限。
- 解绑删除本地连接及加密令牌；解绑当前账号后不自动切到其他账号。
  解绑不会撤销 GitHub 上的令牌，需要撤销时在 GitHub 设置中处理。

令牌使用 Fernet 加密后保存在 SQLite，独立加密密钥保存在本机系统凭据库。
Windows 使用凭据管理器；Linux 需要可用且已解锁的 Secret Service。
系统凭据库不可用时不会退回明文文件。数据库备份本身不包含解密密钥，
迁移到新主机后需要重新连接账号。账号凭据不进入 Agent 上下文或仓库记忆。

当前提供访问令牌连接，尚未提供浏览器 OAuth/设备码登录或自动同步 GitHub CLI。
连接账号后可在仓库页面下载源码；不会自动启用真实 Issue 接入、Issue/PR 发布或自动合并。
详见 [账号绑定设计记录](docs/adr/0014-github-account-binding.md)。

## 仓库下载与运行

1. 在“仓库”中点击目标仓库的“管理运行环境”，然后选择“下载最新版本”。
   下载使用当前 GitHub 账号，绑定到固定提交；令牌需具备仓库内容读取权限。
2. 下载后检查“运行配置”中的语言、安装、测试、启动命令和端口。
   自动识别支持 Python、Go 和 npm / TypeScript；无法识别时先保存手工配置。
   Python 会读取 pytest 配置和开发依赖声明；识别为 pytest 且存在
   `requirements-dev.txt` 时，安装命令会包含测试依赖。
3. 需要下载依赖时勾选“安装时允许联网”并保存，然后点击“安装环境”。
   默认不允许安装联网；测试始终断网。私有依赖不会自动获得 GitHub 凭据。
4. 点击“执行测试”查看命令结果。点击“启动项目”，监听成功后通过“打开项目”
   进入独立的本机地址。服务应监听 `0.0.0.0` 和配置中的端口。
5. 使用停止按钮结束项目；启动后的环境最多运行 30 分钟。
   后续可从同一源码版本和保留的数据卷重新启动，无需保持项目常驻。

Docker Desktop 必须已启动并使用 Linux 容器。首次安装按语言下载官方镜像。
镜像固定为 Python 3.13、Go 1.25、Node.js 24 的 Debian 配置，实际使用的镜像
内容 ID 会随环境记录保存。命令仅在非 root、受资源限制的项目容器中执行。
Python 虚拟环境位于 `/workspace/home/venv`，项目目录为 `/workspace/project`。

安装和测试每次最多 10 分钟。源码、配置、命令结果和日志会保留；重新安装会重建
项目数据卷，清理按钮则删除该环境的源码、数据卷和网络。当前需要手工清理旧环境，
尚无数据卷总磁盘配额。允许安装联网时采用普通 Docker bridge，能访问可达网络服务。
项目启动后的网络由独立预览转发提供访问，不直接连接外部网络。

当前下载的是 GitHub 固定版本源码归档，不含 Git 历史、子模块或 LFS 实体。
含链接或不安全路径的归档会被拒绝；大型仓库、复杂多服务项目、非标准依赖可能需要
后续支持。下载上限为压缩 32 MiB、源码 128 MiB、20,000 条归档记录。
项目预览使用 `127.0.0.2`，与管理页面的登录 Cookie 隔离。

安装失败和测试失败只作为执行结果，不会直接创建问题、开始修复或提交 PR。
真实疑似问题由后续 Agent 源码分析产生，不能把失败本身当作已复现的项目缺陷。
详情见 [仓库执行设计记录](docs/adr/0015-repository-execution.md)。

## 自动分析与疑似问题

1. 在“运行配置 → 仓库分析模型”填写模型名称、服务地址、API Key 和接口类型，
   勾选“启用仓库自动分析”后保存。保存仅代表配置完成，实际调用时验证服务兼容性。
2. 安装后的测试或启动尝试结束，系统会自动排队分析，不要求先由你打开项目。
   现有执行记录也会在升级后补入队列；没有模型配置时显示“等待模型配置”。
3. Agent 读取限定范围的源码、执行记录和当前仓库同版本记忆，经“仓库分析 →
   问题调查 → 复现辅助 → 独立审查”交接，给出疑似问题、文件行号、依据与复现步骤。
4. 工作台提醒有待复现的问题时，你再操作目标项目，并在该仓库的“仓库自动分析”
   面板直接点击“复现成功”或“未能复现”，复现说明选填，无需重复勾选。
   点击“复现成功”即本人明确确认；旧配置或旧执行结果的报告不能确认新问题。

这是工作台自身的模型配置，与目标项目的聊天模型无关。支持 Responses 与
Chat Completions 兼容服务；模型需支持工具调用及结构化输出。密钥通过系统凭据库
支持的加密存储保存，不进入目标容器，也不会回显。更换服务地址需要重新填写密钥。
启用分析后会向所选服务发送限定范围的源码、日志和记忆；自动脱敏并不能识别所有秘密。

本阶段读取既有运行记录，不自动执行模型生成的测试或浏览器探索。源码数量、大小和
读取次数均有限制，报告会显示覆盖范围。SDK 工具与交接已通过测试模型验证；
真实服务调用需要配置模型后验收。确认后的真实问题目前保存为“已确认 · 待接入修复”，
尚不会修改目标源码或创建 GitHub Issue/PR。详见 [自动分析设计记录](docs/adr/0017-repository-analysis.md)。

## 环境故障诊断

安装、测试或启动失败后，运行环境页面自动显示原因、日志依据和处理建议。
常见错误先通过本地规则分析；例如安装关闭联网时，DNS 失败可能进一步导致
“No matching distribution found”，应先恢复依赖源访问。
“Ran 0 tests”会提示测试收集问题，并根据项目声明提示核对 pytest 与测试依赖，
不会将没有运行测试视为已验证。

有可用配置建议时，点击“应用建议并重新安装”会保存建议并排队安装。
建议绑定失败任务、源码版本和当时的配置；修改配置或重试后，旧建议只能作为
历史记录查看。诊断本身不执行命令、不修改源码，也不代替问题复现或测试结果。

复杂故障可启用真实模型诊断，在启动服务的环境中设置：

```powershell
$env:REPOWATCH_DIAGNOSIS_ENABLED = "1"
$env:REPOWATCH_DIAGNOSIS_MODEL = "<模型名称>"
$env:REPOWATCH_DIAGNOSIS_API_KEY = "<专用模型密钥>"
$env:REPOWATCH_DIAGNOSIS_BASE_URL = "https://api.openai.com/v1"
$env:REPOWATCH_DIAGNOSIS_API = "responses"
.\scripts\start.ps1 -Background
```

不要把真实密钥提交到仓库。兼容服务可将 API 模式设为 `chat_completions`；
服务和模型需要支持工具调用及结构化输出。地址只接受 HTTPS 或本机 HTTP。
目前通过启动环境配置，尚无 WebUI 模型配置表单，也不会自动使用通用的
`OPENAI_API_KEY`。修改后需要重启服务，页面会显示是否配置完成。

真实诊断复用三个角色，以 SDK 原生 handoff 依次交接：
`repository_analyst → reproduction_assistant → independent_reviewer`。
输入限于脱敏后的失败日志、执行配置和限定大小的依赖清单，不提供 GitHub
凭据、宿主机执行或发布工具。脱敏不能保证识别所有自定义秘密，启用前应确认
目标项目日志和依赖清单可以发送给选定的模型服务。
调用失败或超时会保留本地建议，避免阻塞环境任务。

WebUI 区分“本地规则诊断”和“模型诊断”。明确的安装断网问题直接给出规则建议，
无需消耗模型调用。SDK 交接已通过测试模型验证，真实供应商的端到端调用仍待配置后验收。
详情见 [故障诊断设计记录](docs/adr/0016-execution-diagnosis.md)。

## Windows 启动

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
npm.cmd ci
npm.cmd run build
.\scripts\start.ps1
```

启动地址默认是 `http://127.0.0.1:8765`。端口被占用时脚本会选择后续空闲端口。
首次访问需设置至少 10 个字符的本地管理密码，没有预置管理员密码。

后台运行：

```powershell
.\scripts\start.ps1 -Background
```

启动脚本返回进程号、实际地址与数据位置；日志位于 `data/logs/`。
服务只绑定本机回环地址，不应直接暴露到局域网或公网。

## 体验第一阶段

1. 登录后选择“运行样例”。
2. 等待“待人工复现”状态，查看问题证据。
3. 使用总条数 `20`、页码 `3`、每页条数 `10` 执行样例。
4. 检查预期空列表与实际结果，勾选本人已操作复现，再提交确认。
5. 查看“交接记录”和“本地草稿”。确认后的五项断言只针对内置函数。

将页码改为 `1` 时，本次输入不会复现问题，确认成功按钮保持禁用。
提交“未能复现”后，不会生成修复或发布草稿。

这些操作不需要 GitHub 或模型 API 凭据，也不会向 GitHub 发送写入请求。

选择“已有 Issue 样例”可验证另一条路径：后台创建固定来源的内置 Issue 样例，
自动执行复现、修复和五项断言，生成三份本地材料，不出现人工确认表单。
它不是从 GitHub 下载的 Issue，不代表真实 Issue 接入已经完成。

## 来源与审批

- 系统自行发现：必须亲自复现并确认，才能创建 Issue 草稿或开始修复。
- 已有 Issue：无需人工复现，必须通过当前任务的自动验证；之后仍需修复测试和审查。
- 自动验证失败：暂停并在 WebUI 提醒，可重试，不自动转成人工复现关卡。
- 来源由后台入口确定且不可修改；客户端不能提交来源或验证证据来授权。
- 已有 Issue 不重复生成 Issue；两条路径都不提供合并或自动合并功能。
- 旧任务升级后仍按“系统发现”处理，已有快照和人工确认继续有效。

真实系统发现已支持分析报告和个人复现反馈，但修复与发布仍未接入。
已有 Issue 路径仍仅实现受控样例；真实 Issue 身份核验、去重和接入属于后续阶段。
详见 [来源分流设计记录](docs/adr/0013-origin-dependent-reproduction.md)。

## 仓库记忆

在“仓库记忆”中选择仓库，可以添加项目结构、环境与启动、测试约定三类知识，
填写适用的完整代码版本。手工知识标记为未验证，不会成为人工确认依据。
可以搜索、按分类或版本筛选、编辑、归档、恢复，并查看修改记录。

- 六个 Agent 共用记忆服务，但仅接收当前任务仓库、完全相同代码版本的有效记忆。
- 每个角色按相关分类和新近程度读取，最多六条、6,000 个 JSON 字符。
- 确认复现后自动保存带来源任务和证据的问题记忆；未能复现会单独记录。
- 已有 Issue 样例保存“自动验证”记忆，与“人工复现”证据明确区分。
- 样例补丁通过验证后保存样例修复经验，不将其标记成真实项目的已合并修复。
- “问题与复现 → 记忆引用”展示提供给各角色的记忆及当时版本。
- 流程产生的证据内容不可手工改写；归档只停止后续读取，不清除历史引用。
- 旧记忆不能替新问题确认复现，也不能赋予发布或合并权限。

首次升级启动会补入当前样例版本已有的复现与修复证据，不修改任务快照。
版本不匹配的记忆仍可查看，但不会自动应用于新版本。当前没有语义向量检索、
跨版本经验推断、自动过期清理或真实模型的经验总结。固定样例模型接收记忆上下文，
但其预定义修复行为不会因此改变。详情见 [记忆设计记录](docs/adr/0012-repository-memory.md)。

记忆与任务共用 `data/repowatch.db`，迁移时随数据库一起保留。
请勿在知识内容中填写密码、API Key 或其他凭据。

## 状态与恢复

默认数据库为 `data/repowatch.db`。设置 `REPOWATCH_DB` 可使用独立数据库。
测试与实际试用实例使用不同数据库。

- SDK 快照只保存在后台，不接受浏览器上传的快照。
- 快照绑定 SDK 版本、Agent 图版本和样例源码指纹。
- 确认记录与后续任务入队在同一 SQLite 事务内提交。
- 任务使用租约领取；正常停止后可重新领取，意外退出后的租约约 30 秒到期。
- 重复确认不会重复创建后续任务，重复执行不会生成重复草稿。
- SDK 版本、源码版本或快照校验不一致时停止，而不是绕过人工确认。
- 当前执行时间上限为 120 秒，SDK 最大 24 轮，任务最多尝试 3 次。

管理密码仅保存加盐派生结果。数据库仍包含私有会话及运行记录，应保留在受保护的
本机目录中。本阶段没有密码找回入口或远程部署配置。

## 测试

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check repowatch tests
npm.cmd run build
```

浏览器测试应使用独立测试数据库，不能对个人实例运行：

```powershell
npx.cmd playwright install chromium
.\scripts\start.ps1 -Port 8766 -Database data/browser-qa.db -Background
npm.cmd run test:e2e
```

如果测试实例用了其他端口，设置 `REPOWATCH_TEST_URL`。截图输出到
`test-results/`。测试会在自己的数据库中设置测试密码、运行样例并登记一个仓库，
但不访问或执行该仓库。

实际 Docker 验证只运行项目自带的三种语言样例，需要已启动的 Linux 引擎：

```powershell
$env:REPOWATCH_DOCKER_TESTS = "1"
.\.venv\Scripts\python.exe -m pytest -q tests/test_execution_docker.py
Remove-Item Env:REPOWATCH_DOCKER_TESTS
```

普通后台测试默认跳过这些容器测试。真实 Docker 测试会下载官方镜像，
完成后清理测试容器、数据卷和网络。不要对个人实例数据库运行测试。
