# 先取得验收证据，再提交 PR

用户要求 Issue 得到真正解决后才能提交 PR。系统采用可核查的验收门槛：证明修改前问题存在、修改后消失，通过相关回归检查和独立审查后，才能提交 PR；无法复现或验证条件不足时阻塞任务。这一选择优先保证交付证据的可信度，接受部分问题无法自动完成，不以 Agent 自述或仅生成补丁作为成功依据。

对于无测试仓库，先补充能够在修改前失败、修改后通过的回归测试。已有失败检查采用基线比较，只有证明与本次修改无关且未恶化才不阻塞；新增、相关或无法归因的失败均阻塞 PR。

提交前按预设验收协议核验有效证据，创建后再跟进 PR 事件专属检查，两类证据分开记录。若目标问题只能在 PR 环境验证而无其他有效提交前修复证据，保持阻塞，不为取得 CI 而绕过门槛。

2026-11-03 明确：Bug 保持有效的失败前证据／修复后通过；已批准功能与纯重构须在方案中规定新增能力或结构目标及行为保持的证据，不虚构 Bug。最终证据绑定冻结的候选提交及实际内容，不能只用 `HEAD` 代表脏工作区；更新 PR 也必须重新核验。详见[实施契约](../implementation-contracts.md)。
