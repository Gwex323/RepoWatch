# 全局串行执行修复任务

用户需要管理多个仓库，但不要求并行解决 Issue。系统将符合条件的已有及新增 Bug 自动入队，全局同一时刻只执行一个修复任务，并提供按仓库暂停、任务排除和人工调整优先级。这一选择接受较低吞吐量，以控制本机执行资源和任务协调复杂度；Q23 已确定子任务默认串行、同一工作区单写。

用户进一步选择：权限、环境、验证或预算等执行障碍触发阻塞时暂停整个队列，等待人工处理，接受其他仓库任务因此等待。系统保留现场和证据，不能以自动跳过阻塞任务或无限重试代替人工恢复。方案批准或 PR 评审属于正常等待，可释放执行位；暂停期间保留只读 GitHub 巡查和状态同步。

扫描、Issue 修复和 PR 返修统一使用同一个全局重任务执行位，API 和只读 GitHub 巡查独立运行。用户接受导入扫描期间修复任务排队，避免长任务同时争用本机环境。

模型分诊、方案生成与记忆提炼也由 Worker 串行安排，巡检只保存数据及待分析信号。返修仍属于原任务，预算累计；诊断、暂停与执行代次校验见[实施契约](../implementation-contracts.md)。
