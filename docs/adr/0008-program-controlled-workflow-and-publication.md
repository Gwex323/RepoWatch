# 程序化工作流掌握状态与发布控制权

严格的扫描、修复验收和全局阻塞规则由程序化工作流管理，Agent 在任务内自主分析、修改并提交结构化证据；专门的发布程序核验当前代码版本与证据后执行 GitHub 写入。用户选择将流程与发布权限放在可核查的程序规则中，接受显式状态和证据协议的实现成本，不让主 Agent 自行决定所有阶段和最终发布。

角色之间经 Harness 的结构化任务与结果协议交接，子任务默认串行、工作区单写，独立审查使用只读会话。按当前运行授予工具，供应商密钥由宿主模型适配层持有，GitHub 写凭证由发布程序持有，验收记录由程序收集和核验。
