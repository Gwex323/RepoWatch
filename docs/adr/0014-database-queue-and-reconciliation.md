# 数据库持久队列配合异常对账与人工恢复

用户选择数据库持久队列、短事务领取、租约与心跳管理唯一执行权，异常中断后先全局暂停并核对业务记录、检查点、代码、旧命令及远程操作，再由用户处理后恢复。该选择接受应用实现调度和对账的成本，不引入专用任务中间件；GitHub 写入结果不明确时保持阻塞，不以检查点重放或盲目重发作为恢复办法。

递增执行代次约束旧 Worker 和结果写入；暂停／取消需先确认旧写命令结束或隔离再释放执行位。已记录的正常等待不当作异常；用户可明确启动有界排障但不自动解除全局暂停。预算、数据库故障和备份恢复核对见[实施契约](../implementation-contracts.md)。
