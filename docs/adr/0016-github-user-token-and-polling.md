# 本地 GitHub 接入默认用户 token 与条件轮询

用户选择本地保存 GitHub 用户 token 并按仓库权限适配，本人／组织仓库在适用时使用 fine-grained PAT，第三方 Fork 贡献使用具备对应权限的 classic PAT 用户路径，避免把 App 安装能力假定为任意上游贡献能力。默认通过认证条件轮询同步，接受分页、去重、限额和周期复核的实现成本；认证与同步保留适配边界。

后续用户将初始巡检频率调整为活跃仓库约每 2 小时、空闲仓库每天一次。同步在 API 进程保存数据与待分析信号，Worker 串行模型分诊；同一查询必要页面持久化完毕才推进水位。活跃判定、端点差异、失败健康状态与补偿规则见[实施契约](../implementation-contracts.md)。
