# 五个真实角色的独立模型配置

日期：2026-10-22。关联 Issue #55、PR #56。

## 决定

以 `repowatch/roles.py` 的五个角色为配置单位。仓库分析、问题调查、复现辅助、
代码修复和独立审查各自保存模型名称、服务地址、接口类型、推理强度及加密密钥。
同名角色跨流程使用同一配置；不按九个 Agent 创建位置重复注册配置。

`FLOW_ROLES` 明确各流程所需的角色：分析四个、诊断三个、修复两个。
模型工作流的总开关保留，自动修复另有原有开关。缺少不参与当前流程的角色模型，
不会阻止当前流程；缺少分析模型时任务等待，缺少诊断模型时保留本地规则诊断。

## 存储与升级

- `agent_models` 以 `role` 为主键，分别保存配置、加密密钥和并发版本。
- 旧 `analysis_model` 保留全局启用状态和配置修订号。已有统一配置在初始化时复制到
  五个角色，密钥保持原密文，不需调用供应商或重新读取明文。
- 迁移采用 `INSERT OR IGNORE`，重启不覆盖已修改的角色。
- 单角色保存采用事务和该角色的版本校验，只更新该角色；同时递增全局修订号，
  让记忆 A/B 评测识别配置变化。总开关保存校验全局修订号。
- 空密钥仅保留本角色原密钥，服务地址变化必须重新填写。公开状态只返回密钥是否存在，
  不返回明文或密文；新接口沿用所有者登录、同源和 CSRF 校验。

## 接口与调用

- `GET /api/agent-models` 返回五个角色的公开配置与各流程缺少的角色。
- `POST /api/agent-models/{role}` 保存一个合法角色，正文使用该角色的版本号。
- `POST /api/agent-models/settings` 保存总开关，正文使用全局版本号。
- 旧 `/api/analysis-model` 接口保留兼容：旧的整组保存明确更新全部五个角色。
  新界面不使用此整组保存入口。

每次执行从同一个数据库快照取得所需配置，调用期间固定该快照。
不同配置分别使用各自的传输、密钥、接口适配和推理强度；配置与密钥全部相同时，
允许复用一个模型适配器。SDK 原生 handoff、工具边界、验证和发布条件继续生效。
各角色的 DeepSeek / GLM 兼容选项独立计算。

结果保留实际角色模型与版本，发布正文仍由后端整理，模型不会获得发布工具。
记忆 A/B 评测比较完整角色模型记录，配置变化时不把两轮结果当作同配置比较。

## 界面

运行配置将模型表单与角色说明合并为五张卡片，逐角色保存，显示参与流程和保存状态。
概览使用角色卡片展示职责、模型与配置状态，移除暗示五个角色顺序执行的连接线。
所有角色数据来自后端的同一角色目录，保存模型后刷新工作台状态。
