# 0071：分析工具参数的有界自动纠正

- 关联：Issue #71
- 范围：四个仓库分析角色中的三个函数工具和原生交接

## 原因

`analysis_85bd1409a36647ea` 在问题调查阶段返回未截断的工具调用后，由 SDK 参数解析
抛出 `ModelBehaviorError`，分析直接失败。已有输出截断、报告格式和证据纠正不覆盖
工具参数；修复流程的参数纠正也不会自动应用到分析流程。

## 执行前检查

`StageModel` 在把响应交给 Runner 前，对当前开放的已知工具及交接检查参数 JSON 对象。
源码读取、运行记录读取、范围登记还使用 SDK `function_schema` 生成的同一 Pydantic
参数模型校验字段。保留 SDK 对无参数工具的空参数字符串约定；有参数工具不适用。
不补括号、不抽取 Markdown、不解码内嵌 JSON 字符串、不猜测缺失字段。

响应里任意已知调用参数错误时，整份响应不交给 Runner，因此同一批里的其他有效调用
也不会执行，不会出现范围登记重复或半批读取被误认完成。修正请求使用同一次调用之前
的真实 SDK 对话，并明确要求重新生成所需完整批次；无效响应及其任意文本不进入
纠正上下文。有效响应仍由 SDK 原生工具处理器校验、执行并记录真实证据。

未知工具名继续由 SDK 拒绝，不通过参数纠正扩大工具集合。关闭探索、强制必读及指定
交接仍使用已有规则；失败的函数参数不产生读取额度、证据事件、范围变更或 handoff。

## 预算与安全

`RetryBudget.tool_arguments_used` 在四个角色间共享，最多两个额外纠正请求，不重启
Runner，不重置阶段已用轮数、读取数量/字数、任务期限、超时、截断、报告或证据预算。
超时和截断与纠正组合时仍分别使用原有全局预算。重试前检查剩余总时间，每个请求受
120 秒及剩余任务时间的较小值限制。指定交接的兼容重试也经过这一统一请求循环，
不能绕过参数校验和时限。取消由原任务取消链传播，写入报告保留原有状态和依据校验。

事件只包含已知角色/工具名、固定原因、契约字段路径、是否可纠正及剩余次数；不保存
原始参数、模型正文或校验异常文本。纠正反馈包含服务端生成的 schema，审查意见、源码
或模型输入不能修改它。Langfuse 仅记录事件名称，不上传载荷。

## 2026-10-26：按实际失败补全契约、权限和预算

`analysis_9da31ce04adb4b90` 暴露第一版只做有界纠正的不足：复现辅助仍看到无权执行的
范围登记工具；诊断只有顶层 `items`；high 推理与工具参数共用 3000 tokens。
两次纠正的 usage 均达到上限，尽管 finish_reason 是 tool_calls。这是疑似预算不足，
原始参数未保存，不能断言具体在哪个字符被截断。

`analysis_tools.py` 集中定义角色权限，Agent 工具集合、响应预检、实际函数处理器和
范围持久化使用同一策略。四角色均可读取；范围登记仅供仓库分析、问题调查和独立审查，
本人追加 API 的 owner 权限保留。仓库分析在已有运行记录和源码读取后，须成功登记至少
一个范围项才可首次交接；已有非空范围可直接沿用，未登记成功不能靠交接绕过。

范围调用每批 1–3 项，由同一 SDK schema 和 Pydantic 模型约束，继续使用追加、去重、
版本递增和禁止弱化语义。复现辅助从已登记项整理步骤和观察，需要追加时交给独立审查。
嵌套错误提供例如 `items[0].required_evidence[0]`、固定错误类别和可信 schema 的允许值；
未知字段名替换为 unexpected_field，绝不记录模型值、原始参数或异常正文。
JSON 语法错误只提供长度和位置。事件上限 4096，前端展示嵌套字段、位置和预算提示。

工具调用预算同时留出推理与载荷：high/xhigh/max 预留 5000 推理 tokens，其他预留
2000；读取载荷 1000，含范围登记时载荷 3000。取配置与该预算较大值，上限 12000。
保留用户配置的推理强度；审查报告预算与工具预算也取较大值，不互相覆盖。
仅在 JSON 语法错误且可信 output usage 达当前上限时标注疑似不足，允许预算内翻倍至
12000；合法 JSON、字段错误不会因此扩容。扩容消耗原截断预算，纠正仍全流程最多两次。
扩大预算不能保证任何模型永不返回错误；额度、取消和期限耗尽仍明确失败。

真实运行还观察到报告证据纠正时 8000 输出中推理占 7990，明确 length 截断；随后在
十分钟总期限停止。最终报告的预算也须覆盖推理：high/xhigh/max 在原按验收项计算的
载荷预算之外预留 5000，合计仍不超过 12000；对应报告预留时间最多 360 秒。
不会因此重置重试次数或总时限。支持用合法检查点显式恢复审查，复用真实读取和交接。

真实重放进一步发现最终报告可以把 scope_review 留空。已有范围项时新增本地报告契约：
必须使用当前范围版本、逐项且不重复覆盖全部验收项和执行限制；缺少结论时使用既有
一次报告格式纠正预算，从同一真实证据生成完整报告。仍不合格则停止，不能标记分析完成。
`validate_report` 持久化前再次检查，检查点恢复也适用；未测试项可如实 blocked/unknown，
不要求模型把未通过项改成通过。

## 工作台与旧任务

页面显示参数校验与自动纠正过程，新错误码 `analysis_tool_arguments_exhausted` 明确
说明次数耗尽；旧错误码 `analysis_tool_arguments_invalid` 不声称已经纠正。旧版本失败任务保留
原记录；部署不会批量重排旧分析。没有最终审查检查点的旧任务重试仍完整重跑，不能
从旧事件伪造 SDK 对话或证据；本改动保留的是运行中的同一次分析上下文。

## 验证范围

第一版只执行静态检查和构建，未做真实模型验收，不能据此认定端到端修复。
本轮按用户确认补充离线回归与同任务、同源码、同供应商/模型/high 设置的隔离真实重放。
结果记录在 `docs/repository-analysis-validation.md`；真实重放只运行分析，不启动修复或发布。
