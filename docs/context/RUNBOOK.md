# 文档与规划操作手册

本页只记录当前有依据的方法。所有命令示例均不构成执行授权；操作前确认当前请求、项目根目录和 [AGENTS](../../AGENTS.md)。P0 开发安装与切片验证已有入口，完整产品启停、升级、备份和恢复尚待实现验证。

## 接续或局部维护文档

前置条件：任务允许修改文档；只读任务不修改状态记录。

1. 接续时查看 [NOW](NOW.md)；需要定位时按 [项目索引](../../PROJECT_INDEX.md) 选一个相关入口。
2. 在目标文件搜索标题／关键词，再读取命中段及必要上下文；不展开所有索引链接。全文适用规则不能略读。
3. 确认事实的权威位置后定点修改，保留用户内容。仅在入口、映射或当前状态实质改变时更新相应基础文件。
4. 核对本次改动及直接关联链接；检查相对路径、锚点、角色分工和事实／计划标识。未经请求不扩展到全仓审计。
5. 交付说明修改范围、验证范围与待核实项。无产品变化时不运行产品测试，不为文档检查安装依赖。

## 检查现有 OpenSpec 规划

前置条件：当前任务需要检查规划；环境已有可用 OpenSpec CLI。以下命令在 2026-11-03 开发文档复核中已执行，范围及结果见[本轮验证结果](../document-review.md#本轮验证结果)；后续操作仍须按当时任务核验，若命令不存在，不自动安装。请从项目根目录运行：

```powershell
openspec context --json
openspec status --change build-github-issue-agent-harness --json
openspec validate build-github-issue-agent-harness --type change --strict --json --no-interactive
```

依次核对：context 解析到预期项目；若外部 store 或根目录不一致则停止核对归属，不自动初始化；status 显示规划依赖产物完整；validate 退出成功且无校验问题。保存实际结果时注明日期、变更名和范围。4/4、`isComplete` 或校验通过只表示规划结构／规范状态，不证明实现完成。
