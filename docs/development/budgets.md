# P1 累计预算与有限续期

日期：2026-11-04。范围：任务 2.4 的业务数据及执行端口、E14 预算切片和旧库升级。产品规则见[实施契约：预算](../implementation-contracts.md#预算)与[进度驱动的预算续期](../implementation-contracts.md#进度驱动的预算续期)，任务验收见 [tasks](../../openspec/changes/build-github-issue-agent-harness/tasks.md)。本页说明已实现接口及其集成边界。

## 入口与数据

`application/budgets.py` 提供 `BudgetService` 和逐次执行包装 `BudgetedExecutor`；`budget_accounting.py` 共用计量及守卫，`domain/budget.py` 定义值对象。预算首版迁移为 `0004_budget_ledger`，后续角色／模型／人工加额／图窗口继续升级；当前完整 schema 及[显式停写迁移入口](persistence.md#显式迁移与重启)以持久化说明为准。控制会话、供应商、正式图和前端均已接入 P1 端口。

| 记录 | 内容与约束 |
| --- | --- |
| `budget_ledgers` | 固定归属、初始／当前总额、累计实际用量、预留占用、授权修订、已用于授权的进展水位；追加不清零 |
| `budget_step_plans` | 稳定步骤键及不可变上界；预留失败后也不能用同一步骤键缩小上界 |
| `budget_reservations` | 归属、运行／代次、用途、上界、实际回执、未知占用及生命周期；同一意图不重复调用或记账 |
| `budget_progress` | 宿主验证器提交的目标、稳定事实、类别及产物引用；相同事实不重复推进水位 |
| `budget_renewals`／`budget_renewal_revisions` | 单一待处理申请、输入／账本／进展依据、剩余计划、决定和旧修订；人工操作与事件同事务保存 |

## 授权、计量与执行

`BudgetAmounts` 使用五个整数维度：`active_ms`、`model_calls`、`tokens`、`repair_rounds`、`recovery_rounds`。token 用量与账单费用分别核对。每维采用非负安全整数，初始授权各维为正；未配置的空账本不允许模型或工具消费。初始总额由调用方根据任务及批准工作量解析，再通过本地用户授权，不提供适用于所有任务的通用总额。

`authorize_initial` 保存操作标识、账本预期修订、用户依据及初始额度。已有授权使用有限续期或明确人工加额；数据库同时限制总额／实际累计不减少、归属不转移。授权入口仅供本地人工作用例，拒绝 Agent 身份，不作为仓库工具暴露；已接入控制会话鉴权。

模型、工具和发布前依次调用 `reserve` → `start` → 执行守卫 → 实际操作 → `settle`。包装只在发送意图和审计已持久化后执行回调；持久化失败不返回交付成功。`Orchestrator.guard` 复核当前执行权、暂停、撤销及绑定此运行／代次／用途的已预留意图。模型上界含单次请求、输入及最大输出 token 和超时；工具／发布预留时长，修复／恢复轮数另行记账。

每次 SDK 尝试、同步子任务和后续返修使用可区分的稳定步骤键，继承原主任务的账本。正式适配关闭 SDK 隐含重试，统一 `ModelCalls` 让每次真实重试经过同一包装；用已安装的实际 SDK 与模拟 HTTP 验证了该调用方式。[正式引擎](runtime.md)的父子运行共享根计时与原账本，实际首步模型预留先于任务信封生成。

有效时长使用运行的持久计时点，在预留、发送、核销、心跳和结束时只累计一次；工具／模型预留中的时长占用随实际计时扣除，避免父子步骤重复计时。正常等待释放执行位后不继续计时，新运行接续原累计值。超上界的真实用量仍入账并触发阻塞；真实命令超时后的停止／隔离由后续 Runner 及安全停止实现，不能把预算计量当作已经终止进程的证明。

| 意图状态 | 含义与处理 |
| --- | --- |
| `reserved` | 已预留而未登记发送；可显式撤销，释放占用，不计为模型调用 |
| `dispatched` | 发送意图已落库而未完成用量核销；不能盲目重放或释放执行位 |
| `unknown` | 本地尝试已返回，部分用量未知；已知用量入账，未知维度保留保守占用，可补充核实回执 |
| `settled` | 计量已核销；不代表远端写入结果或业务验收通过 |
| `cancelled` | 未启动意图已撤销；已发送请求不能按此路径当作未执行 |

重复核销不重复记账，已核实字段不能覆盖为更小值；未知 token 不当作零。HTTP 错误后的请求次数照计，无法确认的 token 上界继续占用。旧代次不能通过计量回写覆盖新执行状态。

## 预警、等待与阻塞

默认任一维度达到 80% 时预警，比例可配置；仍足够预留下一步时继续。未实际耗尽但无法足额预留下一步时记录正常预算等待，拒绝发起该步；初始配置不足、尚无进展时展示配置问题，不伪造进展或无进展失败。任一实际授权耗尽、预算撤销或上界违规仍按阻塞处理，保持全局暂停。迁移账本的累计用量若已达到首次授予的额度，也立即登记耗尽阻塞，保留原累计值。

`request_renewal` 从持久事实生成报告，不调用估算模型。报告包括原授权、实际／预留及未知占用、已完成目标、最近有效进展、剩余目标、继续策略、下一目标、有限增量和估计不确定性；未知估计标为“待核实”。新申请建议必须有未用于既往授权的新进展，不能反复引用旧水位自动索取额度；用户仍可通过明确人工作用例调整有限额度，已有阻塞继续保留。

进展端口核对宿主验证器来源、目标／稳定事实、不可变运行快照摘要、归属和真实产物摘要。事实类别为覆盖、反证、有效证据和已核验子问题；模型自述、百分比或无产物的日志不构成提交依据。3.8 已接入宿主核验器、持久事实消费及无进展／振荡检测；各模式的真实覆盖及语义验证由后续相应业务适配生产，P1 使用受控验证器夹具验收。

保存申请与安全挂起在同一业务事务中完成，留存原运行快照和信号；未完成命令或预算意图阻止释放。图检查点与业务库仍按[非原子窗口协议](persistence.md#业务与检查点的非原子窗口)由运行引擎衔接，不能据预算申请已保存宣称图检查点或远端结果已经核实。

## 人工决定与过期刷新

`decide_renewal` 仅接受明确用户的有限增量、依据及预期申请修订。批准原子绑定预算归属、账本、输入／反馈、验收、代码／配置及进展水位；相同操作回读原结果，另一操作重复批准同一内容也只加一次，不同内容或过期依据报冲突。累计实际用量、未知占用、进展／无进展历史和独立运行安全上限不清零。

足额且无障碍的正常等待在核对当前前置条件后重新排队；全局／仓库暂停、预算耗尽留下的阻塞、无进展或扫描条件未满足时继续等待显式恢复。预算视图的 `available` 只表示额度余额，不能当作执行已经恢复。

`refresh_renewal` 是显式人工作用例：从当前持久记录刷新过期申请，保留旧修订及审计，不启动运行或模型。请求方或归属方的输入、代码、配置及验收依据变化时标记仍需核验，批准后保留 `resume_required` 等待；不能以刷新或加额代替新运行／安全恢复。重新考虑被拒绝的申请也需要此明确用户操作，Agent 不能自动反复索取。

拒绝追加保留等待；明确取消保护原任务取消状态及共享依赖；要求改变范围进入方案确认。[本地控制台](local-control.md)已接入这些表单和可到达入口，暂停、命令生命周期及恢复沿用正式控制门槛。

`BudgetAdjustments` 提供明确人工有限加额，绑定当前账本、输入及进展摘要，要求无活跃运行；重复去重，过期依据拒绝。保留实际用量、未知占用、水位、窗口与暂停／阻塞，取消或撤销的任务不会因加额自动启用；不创建伪管理 Run 或仓库。旧续期提案失效须明确刷新，不能静默批准旧依据。

```powershell
backend/.venv/Scripts/python.exe -X utf8 experiments/run.py e14-budget
```
