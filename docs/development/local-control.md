# P1 本地控制 API 与界面

日期：2026-11-04。范围：3.6—3.7 的 API、安全会话与最小人工处理界面。运行内核见[正式运行引擎](runtime.md)，凭据见[P1 供应商](providers.md)。

## 开发启动与边界

前置条件：已安装锁定开发依赖；API／Worker 使用同一绝对 `REPOWATCH_DATA_DIR`；首次运行先在所有写者停止时[显式迁移](persistence.md#显式迁移与重启)。以下命令从项目根目录运行，须已获相应开发运行授权：

```powershell
pnpm --dir frontend build
backend/.venv/Scripts/python.exe -m repowatch.api --port 8765
```

API 仅绑定 `127.0.0.1`，同源提供 `frontend/dist`。启动完成后浏览器通过 URL 片段接收一次引导凭证，前端立即移除片段；凭证不进入服务访问日志。API 不隐式迁移或启动 Worker，打开／刷新页面不启动任务。另一个终端可显式启动诊断 Worker：

```powershell
backend/.venv/Scripts/python.exe -m repowatch.worker
```

`--once` 只执行一次调度；Worker 先做异常对账。停止使用终端中断；浏览器关闭不等于 Worker 已停止。这是开发入口，Windows 安装启动器、服务联动停止和完整产品交付由 P6 实现。普通仓库任务仍需 P2 的工作区／扫描适配。

## 会话与控制路由

每次 API 启动只接受一次、10 分钟内有效的引导，建立 8 小时 HttpOnly、SameSite Strict 会话。所有 API 核对回环 peer、固定 Host 及允许 Origin；变更还必须带会话防跨站令牌。Uvicorn 不信任代理头。错误使用固定分类，不回显提交内容、密钥或原始 SDK 正文；配置、事件与受控日志使用统一脱敏。

`/api/v1` 下提供状态、任务详情、供应商整批导入／手工编辑／显式列表、角色绑定、暂停／显式恢复、补充信息／配置／优先级、独立诊断、初始预算／有限加额／续期决定、阻塞处理和旧运行报告／放弃入口。变更使用稳定操作标识及预期修订，重复回读原结果，过期或同标识不同内容拒绝。模型诊断只登记意图，由 Worker 取得执行位后执行；显式模型列表为有界只读请求。

## 人工处理与事件恢复

任务详情展示固化输入、当前预算、真实进展、窗口／阈值／指纹及 Run。可补充材料、调整任务策略、设置优先级、核对旧运行。待人工事项集中展示阻塞、正常等待和续期申请，提供具体步骤、成功条件与有限重试授权；处理原因后仍需明确恢复，不能用普通确认绕过证据或活跃旧命令。

预算区区分预警、正常续期与耗尽；显示实际、预留及未知占用。有限续期可以批准、改额度、拒绝、取消或刷新过期依据。独立人工加额绑定当前输入／进展／账本依据，可重新核对；不清零累计用量或窗口，不自动解除全局／仓库暂停及其他障碍。所有管理入口在暂停期间仍可用。

`/events` 提供持久游标分页，`/events/stream` 提供有界批次 SSE。事件帧 ID 是业务序号；浏览器断线以 `Last-Event-ID` 续读，每次重连重新校验会话。前端保存会话内游标并按序号去重，收到事件后回源读取业务状态；事件传输不承载任务执行。流关闭后浏览器按有限间隔重连，不长期占用数据库读事务。

## 验证入口

### P3 分诊与验收规范首批接入

2026-11-06 接入 P3 分诊和修复协调器。Worker 对已确认 Issue 和选中的扫描候选进行宿主准入复核，再通过共享引擎的 `investigate` 模式读取输入、保存结构化分析及分诊结果。手动未选择、标签模式未命中或允许标签未配置的 Issue 不自动调用模型；明确选择仍不能覆盖他人 assignee、排除标签或敏感披露判断。初诊缺信息与敏感披露进入正常等待，不因此暂停全局队列。远端读取包含 Issue、完整分页评论、开放 PR 与 timeline 关联 PR 的描述和文件差异；占用及关系判断保留证据。当前仍有专项／真实 GitHub 验收缺口，不能据接口存在宣称整个 P3 通过。

任务详情可查看分诊原因、证据及输入／准入修订，使用“请求接手并重新核验占用”保存意图；请求不会修改远端 assignee。分诊可生成待确认的方案与验收规范，用户也可保存新修订并明确批准。规范 JSON 包含 `objective` 和非空 `criteria` 列表；功能／重构包含 `plan`，纯重构另含 `structural_goal` 与 `behavior_preservation`。内容历史不可覆盖或删除，批准绑定输入、相关反馈、准入策略及目标配置；目标 SHA 单独变化不作废批准。上述版本变化后须重新绑定规范，普通批准不重新启用取消／排除任务，也不解除暂停或执行障碍。

批准后返回原任务分诊，仍须核对当前准入及后续 Issue／PR、扫描、复现和发布门槛。多个独立目标须先收敛／拆分，不能靠批准原多目标列表合并交付。模型分析只说明信息与目标是否充分，不构成实际修改前失败／修改后通过证据。当前 schema 为 `0021_distillation_state`，现有开发数据库须在全部写者停止后显式迁移；测试只迁移临时数据，不隐式升级用户数据库。

专项测试为 `test_triage.py`、`test_formal_triage.py`、`test_acceptance_migration.py` 及任务／API／Worker 的关联回归。浏览器入口 `node experiments/p3-browser.mjs` 使用临时回环服务和 Edge，验证保存、批准、刷新持久化、输入变化失效、暂停可操作及读取不启动任务；报告位于 `.cache/p3-browser/`。SDK 测试使用模拟 HTTP，不代表真实付费调用或 GitHub 写入验收，最新结果见 [NOW](../context/NOW.md#证据入口与时效)。

### P3 修复证据与受控发布

任务详情显示冻结候选的实际内容摘要、修改前后探针结果、回归比较、独审运行及发布意图。Bug／功能须用同一探针取得 base 目标失败与候选通过；纯重构另保存结构目标和前后行为保持命令。缺包、超时、发现数量减少、新 skip、失败身份或原因变化均不能充作通过。最终候选停止处理工具写入，未提交或未跟踪源码变化使原证据失效。处理—Runner—独审按串行阶段交接，独审只能读证据或申请隔离补查。

可修复失败在原预算中循环；每轮完整验证记录一次进展比较，模型规划／实现／审查子阶段不各自消耗无进展次数。有效复现、不同子问题修复和最终候选有不可变产物依据；重复失败达到阈值全局暂停。查看原始日志和指纹后可补充信息／环境、取消、调整有限预算及通过已有阻塞处理与显式恢复入口重试；批准或加额不能代替验证。纯重构行为证据和探针独审引用保存在最终证据包中。

本地候选先完整查重，结果明确无相似才创建 Issue，确认相同则复用原主任务。创建结果未知时先按稳定标记和创建者对账，不按标题重发；新建 Issue 主任务继承候选的预算归属和执行配置。敏感候选停在脱敏待办。查重不明时在分诊依据中查看候选列表，填写补充信息作为依据后使用“关联已确认相同 Issue”或“确认完整查重无相似 Issue”；决定绑定当前查重版本，执行时仍重新读取。

“远端占用与 PR 关系核对”展示评论与 PR 对照，允许确认同一问题、无关、他人处理中或无占用。人工决定及其依据可回读，远端变化后失效。外部同问题开放 PR 正常等待；已合并时核实 merge commit 在目标分支历史中，使用最新扫描和真实探针确认，已解决记录 `externally_resolved`，仍有目标失败才继续原任务。关系或证据不确定不会发布。

发布器使用稳定受管分支、预期旧 SHA 和冻结候选，分别核对上游／发布仓库身份，保留原 PR 唯一绑定。正文含五段结构、单一 Issue 关闭声明、候选来源、验证摘要与 CI 未执行限制，不公开探针源码。默认不 assign／评论；认领评论须仓库策略显式开启，并保存意图与回执。PR 回执未知可用“请求核对远端回执”排队只读核对；按标记、创建者、仓库、分支及 SHA 唯一匹配，不能盲目重发。已关闭受管 PR 不释放绑定或另建。

认领评论只有在本地发布意图已确认、评论 ID／作者／完整正文匹配且未编辑时，才从外部反馈比较和上下文摘要中排除；实际读取结果仍保留该评论。发评后的重读不会增加反馈修订或使功能／重构的当前批准失效。其他新评论、伪造标记或认领评论被编辑仍须重新分诊。`test_claim_comments.py` 覆盖这些边界，`test_repairs.py` 的 `claim` 三种场景覆盖真实 Docker 修复流程。

验证＋独审后保存待提炼意图，绑定来源摘要及反馈修订；它不是已经生成的记忆。开放 PR 等待释放执行位，保留原累计预算。P5 消费仍须核对来源有效性。
