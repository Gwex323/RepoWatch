# P0 可行性门槛汇总（1.10）

日期：2026-11-04。范围：任务 1.1—1.10 的工程、协议、迁移／执行位、本地 Agent、供应商矩阵、Git 对象交接、恢复、调度与编码资产，以及这些切片对 [最终架构第 11 节阶段门槛](../../openspec/changes/build-github-issue-agent-harness/design.md#11-operations-and-stage-gates)的支撑。本文给出 P0 是否放行 P1 的结论；实验细节与限制仍在 [P0 报告](../../experiments/results/p0.md)及各专题页维护。

## 结论

P0 的六项关键切片 E1、E7、E8、E11、E13、E18 均有实际执行结果，依赖锁、最小协议、迁移草案和环境说明已建立，未发现阻断 P1 的硬约束失败。可以进入 P1，但以下缺口不因放行而消失，必须由后续任务承接：

- E1 未读取供应商账单，实际费用仍为未知；不能把 token 用量当作结算费用。
- E11 只覆盖 Windows→Linux 对象往返与内容对账；LFS 实体、子模块对象、完整安装／启停／续作链路未验证，含 LFS／子模块的仓库交付保持阻塞。
- E18 只覆盖正常等待、旧命令阻断、旧代次拒绝和诊断不解除暂停；有界诊断运行的产品实现属于 P1 2.7。
- 真实 GitHub 写入、完整生产容器隔离、前端操作闭环和用户验收未完成；这些不是 P0 切片可以替代的。
- 1.9 的召回结论来自 22 条语料／12 条查询，只用于筛选资产；生产检索质量待 P5 用真实语料重评。

P0 放行不等于产品可用，也不代表 P1 可以跳过存储失败、凭据对账或安全停止等门槛。

## 依赖锁

- Python：`backend/uv.lock` 锁定 80 项记录（含本项目），本地安装 79 项；Python 3.12.5、uv 0.11.29，第二空环境按 `--locked --offline` 复装成功。主要版本为 Deep Agents 0.7.32、LangGraph 1.2.19、SQLite checkpoint 3.1.3、FastAPI 0.162.0、Pydantic 2.14.2、SQLAlchemy 2.1.6、Alembic 1.20.1、langchain-openai 1.7.3。
- 前端：`frontend/pnpm-lock.yaml` 锁定 React 19.3.1、TypeScript 5.9.3、Vite 7.3.7；Node 24.14.0、pnpm 9.12.0，按 frozen lockfile 安装与生产构建通过。
- 本轮没有新增生产依赖，因此两个锁文件不发生变更；这是核对后的有意状态，不是遗漏。编码评测使用的 FastEmbed 0.9.1、ONNX Runtime 与 psutil 仅安装在已忽略的 `.cache/embedding-eval`，不进入锁文件。
- 生产编码运行时的决定推迟到 P5：届时以可选依赖组锁定 FastEmbed 版本，并固定模型文件摘要；默认安装不下载模型，运行时不隐式联网。P1／P2 不依赖该资产。
- Docker 镜像按摘要固定；不把 `latest` 标签当作可复现依据。

## 字段与协议

`protocol_version` 保持 `"1"`，任务信封、模式工具策略、结构化结果与证据包字段未因 P0 实验扩展；31 项协议测试继续通过。迁移草案 `0001_core_draft.py` 覆盖仓库、任务、运行、预算、租约、分诊、信号、产物、发布意图、PR 观测、进度、扫描依赖与事件，但仍是草案；P1 2.1／2.2 落实正式业务端口、唯一约束与幂等人工操作。

恢复意图、调度依赖和编码索引元数据目前是原型／实验记录，不冒充协议 v1 字段。P1 的恢复表与 P5 的索引表需要在各自迁移中正式定义，并保留模型、维度、归一化、距离与语料摘要，避免复用旧维度或静默回退。

## 环境说明

宿主为 Windows，Python 3.12 虚拟环境位于 `backend/.venv`；SQLite 3.46.0，FTS5 可用，`sqlite-vec` 0.1.9 可加载 `vec0`。Git 对象交接通过 Docker Desktop 的 Linux engine 执行；前端使用 Node 24 与 pnpm 9。真实 E1 需要用户在持有凭据的终端运行，本进程不读取密钥。

沙箱会拦截 Windows 临时目录、Docker 命名管道和部分子进程，因此 pytest、Docker 与前端构建可能需要显式批准后在沙箱外执行；沙箱失败不能推断产品故障。项目不记录密钥、完整聊天或个人临时路径，实验结果写入已忽略的 `experiments/results/local/`。

## 进入 P1 的承接项

1. 先完成 2.1／2.2 的业务数据端口、迁移正式化和幂等操作，再接执行位、预算与暂停恢复；不能把 P0 内存／草案原型直接当作生产状态机。
2. 保持 E1 已选配置的复测能力；供应商差异（`max_tokens`、工具选择、交接提示）继续由显式配置和诊断区分，不做跨供应商静默回退。
3. 含 LFS／子模块的仓库在取得实体内容前保持交付阻塞；不得把指针或 gitlink 当实体。
4. 真实 GitHub 写入、费用账单、完整 E11 链路和用户验收继续列为未完成；发布前按对应阶段重新核验，不引用本轮结果替代。
5. 编码模型在 P5 前不加入默认依赖；若提前实现检索，必须先锁定运行时、固定模型摘要并重跑真实语料评测。
