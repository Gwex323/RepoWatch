# P1 业务持久化

日期：2026-11-04。当前范围为正式存储、业务记录、串行调度和只读来源接口，预算计量及续期见[累计预算](budgets.md)，图阶段与持久窗口见[运行引擎](runtime.md)。行为依据为[实施契约 §3](../implementation-contracts.md#3-状态任务标识与执行权)及[§10](../implementation-contracts.md#10-持久化迁移与正常启停)。

## 数据位置与所有者

API 与 Worker 共用 `StorageSettings`，通过同一绝对 `REPOWATCH_DATA_DIR` 指定宿主数据目录。不指定时，Windows 使用本地应用数据下的 `RepoWatch`，其他宿主使用 XDG 数据目录下的 `repowatch`。读取配置不创建目录；SQLite WAL 不支持本配置入口中的网络共享目录。两进程必须位于同一操作系统侧。

| 相对数据目录的位置 | 所有者与用途 |
| --- | --- |
| `business.sqlite3` | 业务存储适配器；仓库、任务、运行、信号、事件及操作意图的权威记录 |
| `checkpoints.sqlite3` | LangGraph SQLite saver；运行内部状态，独立记录 saver 包版本 |
| `artifacts/` | 宿主受控不可变产物归档；完整落盘后登记摘要，消费时核验可用性 |
| `memory-index.sqlite3` | 为 P5 预留的位置；2.1 不创建或安装编码资产 |

业务用例依赖 `application.storage` 中的 `BusinessStore`／`RecordPort`，不引用 ORM 或图 SDK。SQLite 适配器使用 SQLAlchemy 2；每个连接开启外键、5000 毫秒有限锁等待和 FULL 同步，已迁移数据库使用 WAL。业务写事务显式 `BEGIN IMMEDIATE`，异常整批回滚；读取端口拒绝写入。模型、工具和远端调用必须放在短业务事务之外。

## 显式迁移与重启

前置条件：停止 API／Worker 及其他数据写者，升级已有数据前按维护流程取得一致备份。以下仅为操作说明，不构成执行授权。从项目根目录运行，先将 `REPOWATCH_DATA_DIR` 设为选定的绝对数据目录：

```powershell
backend/.venv/Scripts/python.exe -m repowatch.operations.migrate
```

也可显式传入 `--data-dir`。命令先核对已有检查点 schema，再在业务库独占迁移事务中升级，随后显式初始化独立 saver；重复执行保留业务内容及暂停状态，不启动任务。迁移脚本随 wheel 打包。当前业务 head 为 `0014_read_sources`，承接保留的 `0001_core_draft`、任务／预算及控制恢复迁移，新增角色、模型调用、人工加额、运行窗口和只读来源；不自动降级数据。最新隔离包验证结果见 [NOW](../context/NOW.md#证据入口与时效)。

正常业务存储与检查点入口拒绝缺失／不兼容 schema，不创建替代空库，不在 API／Worker 启动时迁移。saver 包版本改变时拒绝覆盖版本记录，需先验证升级。迁移的跨文件步骤也不是原子提交：检查点初始化失败时命令失败，服务保持停止，核对后重跑；不能把单个文件升级成功当成整组可运行。

唯一迁移进程与全部服务停写的完整产品化、跨库维护屏障、备份和恢复仍由 P6 对应任务交付；本入口的独占事务不等于这些能力已经完成。

## 业务与检查点的非原子窗口

阶段交接遵循“业务阶段意图 → 执行 → 业务结果／产物 → 图检查点 → 业务确认”的核对约束。正式引擎执行中的 saver 可能先保存内部图位置，随后宿主才核验及登记结果；只有业务确认绑定实际结果、产物和检查点 ID 才可复用。`stage_intents` 保存这些引用，执行权和恢复用例已接入；图执行位置不能独立改变业务验收状态。

| 中断位置 | 必须保留的核对依据与后续要求 |
| --- | --- |
| 意图已提交，执行结果未知 | 先核对命令、产物及远端操作；不能直接重放副作用 |
| 结果／产物已提交，检查点未保存 | 业务结果作为事实，验证版本与内容后恢复内部进度，不重新发布 |
| 检查点已提交，业务确认失败 | 检查点不证明交付完成；核对业务结果、产物摘要及远端回执 |
| 任一数据库、必要产物或版本缺失 | 拒绝继续执行／发布，保持待恢复；不得退回内存状态假装成功 |

独立数据库之间没有共享 SQL 事务。故障测试证明：图检查点提交后，即使业务事务回滚，检查点仍存在。[异常对账](control-recovery.md#异常对账与显式放弃旧运行26)及产物门槛承接这些窗口；必要 checkpoint 缺失或写入失败停止新执行。

## 不可变产物与 E20 最小故障切片（2.8）

`ArtifactService` 先持久化稳定产物意图，再写同目录临时文件、刷盘、核对 SHA-256，以不覆盖的原子链接发布文件，最后登记不可变产物与业务事件。相同键和内容可回读，内容不同拒绝；摘要、路径、归属和上下文不能更新或删除。落盘与数据库仍非原子，残留意图会阻止新步骤，完整文件可显式核对补登记；无法核实的旧运行放弃时保留失效记录。

`StageResults` 保存阶段结果前核对实际文件、摘要和运行归属；缺失／损坏引用不能推进结果。消费时再次核对，失效产物标为不可用并全局阻塞，旧引用不能重新激活，重建须使用新产物键。该端口保存证据，不替代后续阶段的代码验证和独审门槛。

业务持久化发生操作错误或必要产物刷盘／登记失败后，本进程停止新模型、工具及发布；读取和恢复操作仍可用。重启后须核对旧运行和未完成产物意图，不能退回内存执行。`EventReader` 使用递增业务游标分页读取，支持按任务过滤和重连；事件与业务变更同事务提交。

2026-11-04，8 项产物测试通过，包含不可变身份、缺失／损坏、悬空阶段引用、注入刷盘失败、文件已保存但登记失败、业务意图失败和事件重连。E20 当前仅为注入故障的最小存储切片；双迁移、维护屏障、跨库备份和真实磁盘管理仍由 P6 完成。本次全量后端 241 项通过、1 项 Docker 跳过；依赖锁、wheel 构建及 OpenSpec strict 通过。

## 稳定业务记录与信号

`TaskRecords` 以 GitHub 稳定仓库 ID 和 Issue ID 复用主任务，来源别名持久关联同一任务。对象更新、输入／反馈修订、待处理信号和事件在同一事务提交；同一来源修订出现不同内容报冲突。运行捕获输入、策略及信号集合，不随新输入变化；确认只处理自己领取的信号，新到反馈保持待处理。

六类分诊分别保存，决定绑定运行的输入／反馈／准入修订。旧输入的结果保留审计但不推进新输入；有效决定先保存待交接状态，仍保留执行位，安全结束后才推进任务。策略排除可因相关新事实重新分诊；人工排除／取消保持到明确重新启用，手动准入仍需要选择。人工操作稳定标识及内容摘要同事务保存，同内容重放返回原结果，不同内容或过期修订拒绝。

受管 PR 采用数据库双向唯一约束，关闭仍保留绑定，禁止删除绑定或替换稳定身份；外部 PR 单独保存观测。这里仅实现本地记录端口，真实 GitHub 写入仍待对应阶段。

## 串行队列与前置扫描交接

`Orchestrator` 在短事务中按就绪门槛、人工优先级、自动严重程度／老化、原入队时间和稳定 ID 领取唯一执行位。正常等待、暂停与缺少当前扫描不累计可执行排队时间；重试保留原排队时间及累计值。租约过期保留原持有者并登记阻塞，不自动接管，旧代次不能续约或写回；长执行不持有业务事务。

前置扫描与父任务等待、释放执行位原子提交；新建扫描固定使用原预算归属，共享扫描保留已有归属。受信任扫描协调器提交当前目标 SHA 的已验证结果时，同事务登记就绪并唤醒合格依赖方；该端口不替代 P2 的真实覆盖验收。取消非预算归属等待方仅移除其依赖；取消预算归属方撤销授权、停止后续扫描操作，保留其他依赖并全局阻塞，不转移费用。

释放执行位前必须核对所有已登记命令，`intent`／`running`／`unknown` 都拒绝释放。实际命令控制及核验已由[命令监督](control-recovery.md#实际命令监督)接入，不接受 P0 的测试布尔值作为产品停止证明。

## GitHub 只读来源与记忆事实接口（3.9）

`GitHubReadPort`／`GitHubReadAdapter` 仅提供仓库身份和 Issue 分页 GET，没有创建、评论、推送或合并接口。请求有超时／体积上限，禁用代理继承和重定向；可选受保护凭据仅用于宿主 HTTP。身份保留 GitHub 稳定 ID、规范 owner/name 和默认分支观测，不据此伪造当前目标 SHA。

`GitHubReads` 保存幂等读取意图，同仓同时只能有一个未完成读取。每页追加原始观测、来源事实及对象头；Issue 复用稳定主任务并生成待分析信号，PR 列表项只作观测。仅更新时间变化不制造同内容输入信号，用户排除不被同步撤销。远端版本更旧或顺序不明时拒绝覆盖；失败页不推进成功缓存。ETag 仅在已保存来源完整时使用，无有效缓存的 304 会无条件重读。

返回值分别声明页完成和仓库快照未完成，不以一页替代全量同步。`MemorySourceFacts.repository_facts` 仅暴露同仓不可变来源引用与关联信号，不做推理、摘要、编码或索引。读取中断可核对旧进程后标记失败，不盲目重复请求。P2 负责完整仓库导入，P4 负责巡检／分页调度，P5 接入记忆索引。

`test_github_reads.py` 的 6 项 HTTP 夹具测试通过，覆盖持久化／信号、幂等／排除、时间更新、ETag、失败页与 PR 来源边界；未调用真实 GitHub。E7／E14／E18 正式内核映射见[运行验收](runtime.md#复跑与实验映射)。
