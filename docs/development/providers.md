# P1 宿主凭据与供应商接入

日期：2026-11-04。本页记录 3.1—3.5 的实现边界；进度和最终证据见 [tasks](../../openspec/changes/build-github-issue-agent-harness/tasks.md)，当前状态见 [NOW](../context/NOW.md)。

## 受保护凭据及脱敏（3.1）

`CredentialVault` 是宿主端口，Windows 实现使用 Credential Manager 的当前用户通用凭据，不回退到明文文件或环境变量。调用方指定稳定应用命名空间；每次轮换生成新引用，原运行可继续引用旧修订。创建使用命名互斥及存在检查，不能覆盖旧引用；删除只处理本项目已登记的引用，不枚举其他应用凭据。

`SecretValue` 隐藏文本和调试表示；配置、业务事件、API 错误及受控日志使用统一脱敏器。凭据只在宿主 SDK 构造和发送时解包，SDK 错误转为固定分类，不保存原始错误正文。供应商读取结果只提供配置修订和凭据状态，Agent 工具不持有凭据端口。Windows 同用户进程的内存与宿主能力限制仍存在；P2 容器隔离及完整 E11 链路不由本端口测试替代。

## 批量新增、手工编辑与跨存储对账（3.2）

`ProviderService.save` 接受单对象、数组或仅含 `providers` 数组的包装 JSON，也可由本地表单传入同等对象。支持名称、地址、两类 API、密钥、模型及 `reasoning_effort`，保留显式 token 参数及工具策略。拒绝重复 JSON 键、未知字段、批内重复、已有同名、非法 URL 和无效条目；名称去首尾空格并按大小写折叠查重。批量导入只新增；编辑必须指定供应商和预期修订，省略密钥表示沿用原凭据引用。

跨存储顺序如下：

1. 在业务事务中保存整批意图、名称占用、全部新配置修订及计划凭据引用，内容不含明文密钥。
2. 将新凭据写入受保护库并回读核验，每个成功步骤登记暂存状态；此时任何新配置均不可用，旧配置不变。
3. 同一业务事务一次激活全部修订、活动配置引用和凭据状态，释放名称占用并保存整批结果。

任一凭据准备或激活失败，整批不暴露为可用；只清理本批新引用，保留旧凭据。已确认准备进程退出时，`reconcile` 按预先登记的全部引用清理，包括“凭据已写、业务回执未写”的窗口；不能因普通超时清理健康的保存进程。暂时无法清理的批次保留待对账状态，重复操作回读批次，不盲目重写。保存和导入不调用供应商或模型列表。

## 协议、显式模型列表与有界连接测试（3.3）

`ProviderAdapter` 从已激活的不可变配置修订读取指定 API，不自动切换模型、协议或供应商。`GatewayChatModel` 共用于正式适配与 E1；SDK 自动重试为零，请求具有超时及输出上限，关闭环境代理、重定向和 tracing，禁止供应商后台任务与隐式跨会话上下文。只发本地函数工具并要求串行调用；当前正式入口使用同步、非流式请求。

Chat Completions 按显式配置选择 `max_tokens` 或 `max_completion_tokens`；默认 OpenAI 地址用后者，其他地址用前者。Responses 使用 `max_output_tokens`。接口均设置 `store=false`。工具及结构化结果实际经过锁定 SDK 的 HTTP 夹具，不以普通文本回复证明角色已就绪。

`list_models` 仅接受显式本地人工操作，保存意图后进行一次有界读取；结果未知时不因重复点击重发。列表失败仍可手填模型；保存配置、打开页面和刷新状态不会自动拉取或选择模型。`DiagnosticRunner` 将指定连接测试绑定独立诊断预算及执行位，不要求已导入仓库，测试后保留原全局暂停。受限输出的有效 AI 回执可证明连接成功，即使推理耗尽输出而无正文，也不能据此准入角色。

协议核对来源：[OpenAI 官方函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)，2026-11-04 实际读取；该文档支持串行函数调用字段，第三方兼容性仍以各配置实际测试为准。

## 角色快照与能力准入（3.4）

`RoleService` 保存处理、只读独审及命名子任务绑定的不可变修订。新 Run 在领取事务中解析当前供应商配置／凭据修订、模型、reasoning 参数和绑定修订；旧 Run 继续引用原快照，不静默换模型。任务可在配置中显式覆盖绑定。

`RoleProbe` 在独立有限诊断中实际调用内存夹具读／写工具和只读证据工具，要求结构化交接携带本次工具产生的挑战值，最多四次模型请求。普通文本、连接成功或错误交接均不能标记角色就绪。宿主保存不可变核验产物，只有已结束的对应诊断能登记能力。

缓存作用域包含配置与凭据修订、模型／reasoning、角色、适配器与工具修订；有效期从诊断结束计算，默认一天、最多七天，不能延迟登记来续命。新失败覆盖旧成功，配置／凭据改变后须重新准入。处理阶段同时核对独审角色已就绪；正式引擎及独立子会话见[运行引擎](runtime.md)。

## 有界重试与网关兼容（3.5）

`ModelCalls` 先保存稳定请求摘要及意图；每次真实 SDK 尝试都经同一 `BudgetedExecutor` 预留／核销，SDK 自带重试关闭。默认最多三次，退避有限且不计有效时长；不自动跨协议、供应商或模型回退。工具绑定和结构化输出仍经过统一模型包装。

瞬时服务／限流故障按策略有限重试，鉴权／额度及持续失败进入全局阻塞；未知 token 保留预留，不当作零。已归档成功回读原结果，不发网络；失败或结果未知的旧意图不盲目重发。两类协议和第三方字段行为以显式配置及实际能力测试为准，不推断接口名称相同就完全兼容。

## 当前验证与真实 E1 复测

2026-11-04，凭据及导入专项共 13 项通过，包括实际 Windows 凭据的重启读取、不可覆盖、第二项凭据失败、业务激活失败，以及实际进程退出后的暂存清理。测试只创建随机命名的测试凭据并清理，不读取其他应用凭据。正式适配 9 项及原有 E1 契约 40 项通过。后续角色 6 项、模型调用 7 项专项通过，API 已补齐配置、事件、错误及日志脱敏验收；当前最终全量结果统一见 [NOW](../context/NOW.md#证据入口与时效)。

用户已在受信任终端完成真实复测。2026-11-04 核对报告 `experiments/results/local/e1-20261104T062900500778Z.json`：`execution_mode=live`、`adapter_revision=4`、无组合过滤，完整矩阵 8／8 通过，23 次请求全部 HTTP 200，配置摘要与当前已选配置一致。用量均有回执，费用仍待供应商账单核实。此前缺少凭据的预检记录保留为历史，当前复测阻塞已解除。

真实 E1 通过不自动激活产品角色配置或解除业务暂停。控制台与显式诊断入口见[本地控制](local-control.md)，真实仓库执行接入仍按后续阶段推进。
