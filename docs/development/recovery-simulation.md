# 模拟远端回执与旧代次恢复（1.7）

日期：2026-11-04。范围：P0 的 E8／E18 关键切片，用模拟远端和 SQLite 状态验证回执丢失、旧命令未停止、旧代次迟到写入、正常等待重启及排障不解除暂停。它不是真实 GitHub 写入验证，也不是完整恢复系统。

## 恢复协议

1. 写远端前先把稳定操作键、目标、head／base 和预期修订保存为发布意图；同一操作键只对应一个远端对象。
2. 创建请求返回未知结果时，立即进入全局暂停和待恢复状态，不因超时或异常自动重发。
3. 对账只按稳定操作键查询远端，不凭标题认领；查到则绑定远端 PR 标识，查不到则记录缺失，仍保持暂停等待人工处理。
4. 恢复前核对检查点、产物和远端结果，并确认旧命令已停止或隔离；任一项不满足都不得释放执行位。
5. 恢复时递增执行代次；旧代次的迟到结果只能被拒绝，不能覆盖新状态。
6. PR 正常等待重启按 `normal_wait` 处理，不因存在检查点就误报崩溃；排障只执行有界诊断，不解除暂停、不增加代次。

## 运行

```powershell
backend/.venv/Scripts/python.exe experiments/run.py e8-contracts
backend/.venv/Scripts/python.exe experiments/run.py e8
```

第一条运行不依赖外部服务的契约测试；第二条执行完整模拟场景，报告写入 `experiments/results/local/e8-<时间>.json`。

## 限制

- 远端是进程内模拟端点，没有真实 GitHub 网络、权限、分页或速率限制；不能替代真实创建／查询核验。
- SQLite 只保存 P0 意图和状态，不是最终业务状态机；未实现租约心跳、进程崩溃注入、幂等键过期或多 Worker 竞争。
- 未实现自动重试策略、人工 UI、远端结果永久未知路径和备份恢复后的远端对账；这些在 P1／P2 按任务 2.6、7.4 等落实。
- 结论只覆盖 E8／E18 的最小恢复语义，不表示真实发布链路或完整产品恢复已验证。
