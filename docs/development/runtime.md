# P1 正式运行引擎与进展检测

日期：2026-11-04。范围：任务 3.8 的正式适配与受控夹具验收。预算规则见[累计预算](budgets.md)，安全恢复见[控制与恢复](control-recovery.md)，产品约束见[实施契约 §3](../implementation-contracts.md#无进展检测)。

## 引擎、权限与子任务

`FormalRuntime` 使用锁定的本地 LangGraph／Deep Agents、已准备的 SQLite saver 和 `StateBackend`，不依赖托管运行时。每个阶段先登记业务意图，构造包含实际首步预留的 `TaskEnvelope`，只注册该模式授权工具。框架内置文件／终端工具及未绑定子任务同时在模型入口和执行入口拒绝。处理与只读独审按固化角色选择模型，不共享消息会话；独审不能使用写入工具。

`StagePlan` 由受信任宿主适配提供目标、工具、有限预留、核验器及预绑定子任务。模型返回 `StructuredResult` 后，程序核对输入／配置／代次／代码版本与实际产物摘要；模型的完成表述不等于主任务完成。Worker 仅在宿主核验产物明确记录 `goal_completed=true` 时结束主任务；模型报告的阻塞保留为全局阻塞。

同步子任务有独立 Run、图线程和角色模型，继承原任务快照及预算归属，共享根执行位和代次。委派期间父运行不能发起模型或工具，第二个子任务不能并行领取；子任务结束仅归还父运行控制权，不结束主任务或释放根租约。根心跳计量有效时长，子任务和 SDK 重试不重复计时，退避不计有效时长。

## 持久窗口与安全上限

`ProgressService` 以原预算归属及稳定目标保存窗口、可比尝试和事实消费水位。新 Run、阶段名称、SHA、时间戳及随机 ID 不清除历史。只比较已完成或超时的尝试；运行中的长检查和正常等待不计作失败尝试。

指纹来自宿主核验器给出的语义比较内容，过滤非语义元数据；不能把 SHA 单独当成代码内容证据。进展只接受有实际不可变产物、目标关联和有效版本的覆盖、实验反证、有效证据或已核验子问题。每项事实只消费一次；旧代码上的事实须重新核验，模型百分比和重复日志不能推进水位。

初值为连续 3 次无进展、2 个 A—B—A 重复周期；达到门槛时保存尝试／指纹并全局暂停。`RuntimePolicy` 另固定每目标累计步骤与有效时长上限，默认 32 步／300000 毫秒，单阶段也检查步数；新 Run 或人工加额不能绕过。策略只能在新配置修订中显式设置有限值，运行中不得改写。

实质处理后明确批准的有界重试，只有在对应领取中消费一次授权后才能建立新窗口；原记录保留，尝试、步骤及有效时长均受批准上限约束。取得真实进展前不会提前认定重试成功。阈值是实现初值，生产样本校准仍待后续阶段。

## 检查点、故障与 Worker 边界

阶段结果引用真实产物和实际检查点 ID，业务确认与图数据库没有共享事务。复用已确认阶段及子任务前再次核对检查点和产物；检查点缺失或写入失败停止新执行，不能退回内存继续。预算不足形成的中途安全等待不伪装成已确认阶段，也不直接重放未知意图。根恢复报告聚合全部后代的命令、预留、产物及阶段，放弃根运行同时处理后代。

`Worker` 优先处理明确授权的有界诊断；普通队列仍遵守暂停与唯一执行位。诊断不需要虚构仓库或 SHA。P1 默认 Worker 尚无真实仓库工作区适配，普通任务遇到该缺失会记录 `workspace_adapter_missing` 并阻塞，不在宿主运行仓库代码。P2 接入真实仓库、容器 Runner 和扫描计划，沿用本引擎及核验端口。
