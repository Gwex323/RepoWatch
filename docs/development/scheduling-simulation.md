# 调度依赖与暂停同步模拟（1.8）

日期：2026-11-04。范围：P0 的 E13 关键切片，用现有 Alembic + SQLite 执行位原型验证扫描前置依赖、暂停时只读同步、共享扫描取消和预算撤销。它不是完整调度器，也不连接真实 API／Worker。

## 验证语义

1. 全局暂停时，只读同步只写业务事件／信号；模型调用和任务领取被拒绝，模型调用计数保持 0。
2. 修复任务等待前置扫描时进入 `waiting`，不持有唯一执行位；扫描运行持有执行位并正常完成。
3. 扫描完成在同一事务内结束扫描、删除对应依赖、仅把无剩余依赖的等待方改回 `queued`，随后释放执行位；等待方可以正常领取，不存在“占位等扫描”的死锁。
4. 普通取消只删除取消方自己的依赖并取消该任务，其他等待方继续共享扫描。
5. 撤销扫描预算时安全停止扫描并把其他依赖方置为阻塞，不继续执行、不静默唤醒，也不允许旧运行迟到写入。
6. PR 评审等正常等待记录为 `suspended + wait_reason`，重启分类为正常等待，不误报异常运行。

## 运行

```powershell
backend/.venv/Scripts/python.exe experiments/run.py e13-contracts
backend/.venv/Scripts/python.exe experiments/run.py e13
```

第二条命令创建临时 Alembic 数据库并执行完整场景，报告写入 `experiments/results/local/e13-<时间>.json`。

## 限制

- 使用单进程 SQLite 与 Alembic 草案表，不覆盖多 Worker 竞争、真实 API 生命周期、后台同步循环或前端入口。
- 预算撤销、共享扫描依赖和原子唤醒是原型函数，不是最终状态机；真实实现仍需接入业务记录、事件、租约心跳和人工恢复。
- 未验证真实 GitHub 同步、分页、速率限制、暂停期间的新 Issue 分诊或生产运维；不能替代 E13 完整场景和后续任务 2.3、8.8。
