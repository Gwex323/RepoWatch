逐项核对当前 `repair_model.py`、`repair_workspace.py`、`repairs.py` 及 ADR 0074 后，
本组失败均定位为测试夹具或断言未随现行契约更新，不需要恢复旧的生产行为：

| 文件 | 原失败数 | 根因和处理 |

| `tests/test_review_evidence.py` | 22 | 仍假设模型负责交接和读取；用于旧任务恢复的夹具在现行流程中实际成功，污染后续资格用例。改为断言真实 SDK 控制及执行顺序，明确注入缺失控制动作构造历史失败。 |

## 门禁与覆盖保留

- 后端触发的交接和读取仍通过真实 Agents SDK 执行；审批来自独立模型替身。
  正例断言真实工具执行早于审查请求，保留测试重跑次数及发布次数检查。
- 将“供应商省略交接”改为现行后端控制成功的正例，同时分别注入交接缺失和证据读取
  缺失；两种情况均不产生审查或发布，不以返回的通过文本替代真实动作。
- 读取前暂停阻止工具与发布；非法并行工具响应整批拒绝，只有一次纠正，两个批次均无
  部分执行。未验证交接仍拒绝，断言当前准入层的错误码及无补丁、验证、交接或发布。
- 历史恢复继续覆盖 13 类资格排除、源码改变、测试失败、证据缺失、尝试历史、一次性
  恢复额度和补丁复验；没有重置次数或扩大生产预算。
- 探索额度断言覆盖修复基础值、审查值及修复/审查反馈后的现行累计公式。
  控制动作不计入供应商请求，因此相应格式纠正与推理档位断言跟随真实请求序列。
- 没有新增 `skip`、`xfail`，没有删除失败范围；参数覆盖净增加 2 项：缺失控制动作
  从单一场景扩展为两种，另增加反馈后的额度边界。
