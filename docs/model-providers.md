# 供应商与五个角色的模型选择

关联 Issue #55、PR #56；恢复并整合 PR #48 的供应商功能。

## 使用

1. 在「运行配置 → 模型供应商」新增或编辑供应商，填写名称、baseURL、接口类型、
   API Key 和模型列表。每个模型可独立设置推理强度。
2. 可以点击「拉取供应商模型」，筛选并勾选需要的模型，再添加到编辑列表。
   拉取不会自动保存，不会覆盖手工填写的模型；不支持列表接口时可手工填写。
3. 点击「连接测试」可对指定模型发起一次最多 32 个输出 token 的请求，显示结果和耗时。
   连接成功表示基础接口可用，工具调用及交接兼容性由真实流程验证。测试不会保存草稿。
4. 保存供应商后，在下方「智能体模型配置」设置默认模型，或为五个角色分别选择
   「供应商 / 模型」，点击对应保存按钮。选择现有供应商无需再次填写密钥。
5. 打开「启用模型工作流」。自动修复仍需另行打开原有修复开关。

只有五种角色：仓库分析、问题调查、复现辅助、代码修复、独立审查。
同名角色在分析、环境诊断和修复中共用选择；记忆评测使用分析流程的角色配置。
未单独选择的角色使用默认模型；未设置默认模型时保留各角色原有独立配置。
选择「使用此角色独立配置」会忽略默认供应商，使用卡片下方保留的手工配置。
保存独立配置会同时将此角色切换到独立配置，不影响其他角色的供应商选择。

任务开始时读取同一份配置快照；保存修改影响后续任务，不会改变正在运行的任务，
也不会自动重试历史失败任务。界面、就绪判断、运行事件和结果记录使用实际生效的供应商与模型。

## JSON 导入

可选择 JSON 文件或粘贴文本，支持单个供应商、供应商数组或包含 `providers` 数组的对象：

```json
{
  "providers": [
    {
      "name": "自定义供应商",
      "base_url": "https://api.example.com/v1",
      "api": "chat_completions",
      "api_key": "填写此供应商的密钥",
      "models": [
        {"model": "general-model", "reasoning_effort": "auto"},
        {"model": "code-model", "reasoning_effort": "high"}
      ]
    }
  ]
}
```

`api` 支持 `chat_completions` 和 `responses`。推理强度支持 `auto`、`default`、
`low`、`medium`、`high`、`max`；GLM-5.3 不支持 `medium`。
最多保存 25 个供应商，每个最多 40 个模型；文件上限为 250 KB。
导入只新增，不覆盖同名供应商；整批校验并在同一事务中保存，失败不会保存其中一部分。

## 密钥和检测

供应商密钥由系统凭据库支持的加密服务保存，配置读取接口不返回明文或密文密钥。
编辑时留空保留原密钥；更换 baseURL 必须提供对应新密钥。
默认或角色正在引用的供应商、模型必须先取消选择才能删除。
独立配置的密钥仅在对应角色复用，不自动取用其他角色或供应商的密钥。

HTTPS 地址、回环 HTTP 地址和显式私网 IP 的 HTTP 地址均可配置。
模型拉取最多等待 20 秒，连接测试最多等待 45 秒，不自动重试；响应限制 512000 字节，
最多返回 1000 个模型。检测不使用环境代理、不跟随重定向、不返回生成内容或供应商错误正文。
只有点击检测按钮才会向服务发请求，保存和导入不会调用供应商。
所有接口沿用所有者登录、同源和 CSRF 校验，并校验配置版本。

## 旧配置升级

保留原 `model_providers` 表、加密密钥和角色独立配置，不需要重新导入供应商。
旧版九个按流程区分的选择合并为五个角色；冲突时按「仓库分析 → 自动修复 → 环境诊断」
的优先级采用首个显式选择，并在供应商区展示提示。原始路由保存在数据库设置中，供追溯。
此前已单独修改的角色配置优先保留。升级保留当前模型工作流总开关，不自动开启模型调用。

迁移仅执行一次，后续启动不会覆盖已保存的选择。供应商修改、角色选择和总开关修改都会
递增配置修订号；真实流程按同一快照解析模型，记忆 A/B 评测可识别配置变化。
