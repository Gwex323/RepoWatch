# 供应商与智能体模型

在「运行配置 → 供应商与智能体模型」中新增供应商，填写自定义名称、baseURL、
接口类型与 API Key，再添加一个或多个模型名称。模型名称应与该服务的模型 ID 一致；
推理强度可按模型单独保存。保存只记录配置，实际调用时才验证模型、工具与输出格式兼容性。

默认模型适用于没有单独选择的智能体。仓库分析、自动修复、运行诊断的各个角色均可
单独选择「供应商 / 模型」，包括不同流程的独立审查员。当前九个角色都使用真实模型
调用；固定样例演示中的模拟智能体保持模拟行为。记忆评测使用仓库分析的角色选择。
运行中的任务固定其启动时的配置，新的选择对后续任务生效；切换模型不会自动重试旧失败任务。
自动修复仍需另行启用。

原有模型配置保留在「原有默认模型配置」中。未指定新默认供应商时继承该配置；
保存原有配置会将默认选择切回该配置，已单独选择的智能体保持不变。

## JSON 导入

支持选择 JSON 文件或粘贴内容，可导入一个供应商、供应商数组，或如下对象。
导入只新增，同名冲突会拒绝整批导入；不会覆盖已保存的供应商。

```json
{
  "providers": [
    {
      "name": "自定义供应商",
      "base_url": "https://api.example.com/v1",
      "api": "chat_completions",
      "api_key": "填写此供应商的密钥",
      "models": [
        {"model": "general-model", "reasoning_effort": "auto"},
        {"model": "code-model", "reasoning_effort": "high"}
      ]
    }
  ]
}
```

`api` 可选 `chat_completions` 或 `responses`，默认前者。
`reasoning_effort` 可选 `auto`、`default`、`low`、`medium`、`high`、`max`，默认 `auto`。
GLM-5.3 不支持这里的 `medium` 设置。最多保存 25 个供应商，每个最多 40 个模型。

密钥由本机系统凭据库支持的加密服务保存，读取配置不返回密钥；编辑时留空保留。
更换 baseURL 必须填写对应新密钥；正在使用的供应商或模型必须先取消选择才能删除。
导入文件本身可能包含明文密钥，请自行保管；应用不提供带密钥的配置导出。

## 运行契约（Issue #47）

`model_providers` 保存供应商与加密密钥，`agent_model_settings` 保存默认和按流程区分的角色选择。
SQLite 迁移只新增表，保留 `analysis_model` 原有数据。配置写入使用统一递增版本和事务；
导入失败整批回滚。所有配置接口受已有本机登录和 CSRF 保护，校验错误不回显提交密钥。

模型调用开始时一次读取并解密本流程的配置快照，分别建立禁止环境代理和跨地址重定向的
客户端，不把密钥放入提示词、仓库容器、事件或模型身份记录。角色选择既改变实际 SDK
模型，也改变该角色的推理设置及输出格式适配。客户端在成功、异常和取消时统一关闭。
模型身份记录包含供应商、模型和配置版本；成对记忆评测检测默认或角色选择发生变化。
