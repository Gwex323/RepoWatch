# 系统协调策略（#80）

更新：2026-10-29。第三阶段已实现并通过定向验证和独立 review，PR #91 已于 2026-10-29（Asia/Shanghai）合并为 `74b0918`，部署未核验。
本阶段不包含第四至六阶段的自身代码维护、合并、部署或完整链路验收。

## 配置与启用

1. 在模型设置显式选择 `system_coordinator` 的供应商、模型和推理强度，或保存该角色独立配置。
2. 打开原有模型工作流总开关。协调角色不继承默认模型，未配置不阻塞原五个业务角色。
3. 在“系统故障”打开“协调新发生的系统故障”。该开关默认关闭，与规则恢复开关独立。
4. 如需备用模型，先保存备用路由，再显式勾选失败后使用的授权；仅保存路由不授权调用。

旧版五角色保存、供应商导入及启动迁移均保留协调选择。协调配置修改不会重置业务预算。
协调备用供应商和模型被引用时不可删除，须先取消备用路由。

## 事实与权限

协调输入仅含脱敏故障事实、事实键、未知信息、允许动作、根任务预算和最近三条动作回执。
模型没有工具、shell、SQL 或 GitHub 写入能力，只能输出严格结构化计划。
服务端检查发生项、依据摘要、事实引用、动作、验证方式、当前账号、授权版本、租约和预算。
日志和模型输出均不构成授权；调用数量异常不得归因为 JSON 或网络错误。

允许的计划动作：

- `retry_repair`：仅针对原白名单修复错误，仍需原规则恢复和修复开关、原依据、退避及额度检查。
- `wait`：仅业务流程可选择，等待原步骤验证，有界超时，不把排队等同恢复。
- `request_authorization`：记录需要新增授权，不自动扩大权限。
- `blocked`：记录明确停止原因，不执行其他动作。

协调不会确认新发现、批准自身补丁、放宽验收、修改业务源码、合并 PR 或部署。
只有原来源适配器的真实验证证据才能将故障标记已恢复；协调收尾保留已恢复或已忽略状态。

## 领取与预算

仅诊断启用后新发生、尚未建立协调任务的最新待处理或受阻发生项；显式历史补录不自动处理。
同一发生项最多一个持久化任务，同根任务沿用第二阶段独占执行权；业务正在占有根任务时等待。
来源已取消、过期、完成或较小预算耗尽时，在领取及请求边界停止，不调用模型。

每根任务协调模型最多两次请求，包含第一次请求和最多一次纠正或失败重试；诊断租约 250 秒。
第二次请求仅在事先授权时使用已保存备用路由，否则仍使用原模型，不隐式切换。
请求、纠正、耗时、已报告令牌计入原根预算；分析的 32 请求/1800 秒、验收的
12 模型请求及来源期限等较小约束继续生效。未知令牌或费用不伪造为零，费用仍显示未知。
模型全部不可用时保留本地台账，降级到已有规则白名单或受阻，不递归生成协调故障任务。

## 进度、通知与回退

工作台显示诊断、事实引用、未知项、下一动作、预期验证、请求/令牌/耗时/费用与停止原因。
修复适配器返回真实排队回执，排队仅显示“尚未验证通过”。
完成、最终受阻和新增授权需求按任务状态版本产生持久化通知；普通等待不重复通知。
通知跳转到对应故障详情，可以标为已读；通知及任务按当前来源访问范围读取。

关闭协调开关后停止新领取，在运行请求边界撤销旧计划；已排队的协调修复同样复核配置版本。
关闭协调不会关闭原有独立规则恢复或改变人工操作。重启不重放已建立任务，过期诊断保留未知回执。
等待来源验证最长使用根任务 5400 秒窗口，来源失败、取消或额度耗尽时提前停止。

数据库只做加法初始化，不删除原任务、配置和预算。回退首选关闭协调开关；本阶段未执行正式数据库迁移演练或部署切换。
验证范围和审查记录见[交付验证](system-coordinator-80-validation.md)。
