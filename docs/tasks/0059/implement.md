# 实施顺序

1. 范围/证据/发布决定的数据结构、版本与追加服务。
2. 分析工具、结构化范围审查、finding 映射、旧记录回退。
3. 修复上下文、独立覆盖审查、受信证据及完成计算。
4. 发布引用模式与幂等检查；原 Issue 新鲜度校验。
5. owner API、进度与待办界面、记录和继续入口。
6. README、ADR、静态自审及中文 PR。

## 实施与静态 review 记录

已实现范围账本、分析登记与独立范围审查、逐项修复证据、Refs/Closes 发布决定、
本人观察 API、范围进度和继续入口；README、五个角色说明与 ADR 同步。

静态 review 发现并修正：

- 完成依据与分析的当前执行身份统一，新的执行记录不能沿用旧验收结论。
- 所有持久化发现都需映射；继续审查保留既有发现和人工状态。
- 跳过/排除项必须核清；新增回归跳过或全套跳过数增加不能生成完成证据。
- 不同 PR 的证据不能拼接；改动相关路径的补丁不能沿用原版本的无缺陷证据。
- 最近失败的本人观察否决旧通过记录；历史数量上限不能挤掉当前有效证明。
- 证明绑定实际补丁、范围、源码、审查及验证摘要；本人观察事务内核对所选补丁摘要。
- 模型文本中的关闭关键词统一清理，后端单独生成可信引用；重试沿用持久化发布意图。
- 前端切换分析会重置表单，所有排除项均展示分类和说明。
