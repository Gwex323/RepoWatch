# 通用修复范围与证据闭环

关联 Issue #59；用户已批准实施通用方案。

## 目标

所有仓库的 Issue 和系统发现均拥有持久化任务范围、逐项结论及来源明确的证据。
单个补丁批准不能代表原问题整体完成；部分修复可提交，未完成项继续保留。

## 已确认事实

- 当前 Finding/Review 仅保留缺陷和文字限制；Repairs 每个 finding 创建一个任务。
- 分析执行经过四个角色交接，修复经过修复角色与独立审查交接，总角色数仍为五。
- 发布器现有关闭引用无整体范围检查；桌面离线范围已记录 excluded/uncovered。
- PR #58 尚未合并，本分支承接其可信原 Issue 关联修复。

## 要求及验收

- R1：范围绑定原始问题快照、仓库、代码版本及分析；模型追加范围，独立审查冻结；已有要求不可删除或降级。
- R2：每项记录待调查、已确认、待验证、已验证修复、已核验无缺陷或受阻；关联 findings/修复/证据，遗漏为待调查。
- R3：后端校验执行、补丁、范围版本和角色审查来源；模型自述、排除/跳过测试或旧证据不能完成必要验收。
- R4：区分补丁批准和整体完整性；部分使用 Refs，完整且当前组合证据有效才允许 Closes；重试不可更改既有发布意图。
- R5：任务详情展示进度、剩余项、证据和续办入口；旧任务为完整性未核验，重启不补成完成。
- R6：新分析重用同一 Issue 的范围并保留历史，原问题/源码改变使旧结论失效。
- R7：自动修复启用且原确认有效时，后台自动补齐当前范围审查、复核并登记已有真实测试证据、执行支持的剩余验证；不能要求用户代替系统抄录已有测试结果。
- R8：同一确认问题的真实验收失败自动反馈修复，有持久化历史和有限额度；外部服务、客户端能力、授权或额度不足必须显示具体阻碍，不能降低验收条件或无限重试。
- R9：模型输出截断有一次有界恢复；可恢复的供应商故障在原时限与次数内自动接续，保留安全错误类型、HTTP 状态与应用栈位置。明确续跑可重开已过期的时间窗口，但不得清零请求、运行次数或改动要求和历史证据。

## 边界

不新增 Agent，不改变本人复现/账号/源码/补丁验证门槛，不自动合并，不新增未经隔离的主机执行通道。
平台验证不足时明确受阻，平台能力由现有执行记录或本人核验记录补充，不能用模型文本冒充真实执行。
静态检查和构建；本次不新增/运行测试，不触发真实模型或用户仓库修复发布。
