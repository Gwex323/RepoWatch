## 数据流与边界

- 新运行 claim 时建私有额度记录；失败后在同一事务中决定停止或排队，旧失败任务不扫描。
- 自动续办仅接受最终审查角色、允许的固定错误、仍有效的真实检查点、当前源码/模型/执行/Issue/范围以及可用的账号流程。
- 退避写 retry_after，队列可继续调度其他任务。已安排的恢复如果失效直接停止，不降级为完整探索。
- 所有 delegate 调用统一经过 request，包括主干原来的交接纠正分支；请求前预占，超时和崩溃不退还。
- 纠正次数在决定重试时写数据库，跨自动续办、重启与普通 retry 不减小。32 次请求、三次续办、1800 秒总期限独立限制；关闭模型期间排队也会到期停止。
- 运行版本检查覆盖预算、状态激活、检查点和报告提交。取消、过期运行不得覆盖新任务结果；失败不会提交半份报告或不合格发现。
- 主动的新范围审查通过原 owner 入口改版本，先归档上一链额度和诊断；此例外不用于普通 retry 或模型自主登记。
- JSON 诊断仅固定原因/可信 schema 路径/数值坐标；未知字段名脱敏，不包含原始报告、参数、错误值或异常正文。
- 页面通过原轮询读取状态，等待期间无需点击重试；额度耗尽禁用 retry，显示具体原因，记录保留。
