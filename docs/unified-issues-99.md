## 行为与范围

- 仓库导航为环境准备、项目分析、Issue、修复、PR，移除独立“问题与修复”步骤。
- Issue 页默认同时显示 GitHub Issue 和项目分析发现，可筛选全部、GitHub Issue、分析发现。两类条目明确标记来源；本地发现没有虚构的 GitHub 编号，不因列表展示而发布远程 Issue。
- GitHub Issue 继续支持同步、原链接和基于当前环境提交分析；提交后进入项目分析。
- 分析发现沿用当前所选源码环境的分析记录，可切换分析记录查看历史发现、依据及历史复核，保留误报、未能复现、已解决和当前版本续办等服务端校验。记录显示时间、源码版本及当前/历史标记。
- 模型报告、任务验收和分析进度归项目分析；补丁、测试、独立审查和修复任务归修复；远程发布记录归 PR。
- 分区及来源筛选通过隐藏既有组件保留表单草稿与分析选择。切换源码版本会清除旧分析定位，避免把旧环境的分析 ID 带入新环境请求。
- `reproduction` 旧分区映射到 Issue；概览待办与问题列表带入环境及分析 ID，分析报告中的发现入口进入 Issue 的分析来源，通知按实际任务进入 Issue、分析或修复。

此改动复用既有 API，不新增数据表、不迁移发现为 GitHub Issue，也不改变修复资格、开关、权限、预算及远程发布规则。项目没有可用的 `.trellis` 项目规范或上下文脚本，按仓库 AGENTS、现有组件、接口与文档实施。
