日期：2026-10-30（Asia/Shanghai）。分支 `feature/unlimited-workflows-101`，基础 `d22226a`（PR #100 合并版本）。对应中文 Issue #101 在修改源码前创建。

## 用户确认的范围

取消两类限制：累计模型请求、令牌、纠正、自动续办及任务总时限；禁止新增生产文件、修改既有测试、依赖清单、构建配置和 CI 的补丁规则，以及单文件 32,000 字节、补丁总大小和文件数量上限。

## 实现

- 分析：移除阶段探索/读取次数和字符累计额度、阶段时限、SDK 总轮数、纠正次数、32 次请求、30 分钟及三次报告续办限制。检查点有效时继续使用已读取的证据；退避为 10/30/60 秒，后续沿用 60 秒。
- 修复：移除尝试次数、任务总时限、探索轮数、源码读取累计额度、工具参数/验证/审查纠正次数和发布重试次数限制。SDK 使用已安装版本支持的 `max_turns=None`。
- 验收：移除运行、请求、逐项纠正及派生修复次数限制，不再设置总截止时间；暂时性故障继续延迟恢复。真正的行为失败仍保存为失败证据，不能通过无限改测试冒充成功。
- 共享恢复、中央调度、自身维护和发布后原任务验证：额度不再参与资格判断，真实用量和幂等回执仍累计；中央调度的诊断不因来源历史额度耗尽而被拦截。失效依据和取消仍阻止执行。
- 环境诊断：取消六轮和 90 秒总时限，保留独立请求超时和有限租约。
- 租约：运行中的 guard 续期共享根任务与对应业务任务的有限租约；失联进程仍会到期释放。延期用条件更新核对动作身份及业务状态。
- API 的额度上限和任务截止时间返回 `null`；页面显示“不限额”和累计用量，取消客户端硬编码的验收次数禁用条件。

## 补丁与验证

补丁仍提交完整 UTF-8 文件内容。既有文件需先读取并匹配原始 SHA-256；新增生产文件使用空原始哈希。`regression_paths` 继续只接受独立新增回归文件，不允许以既有测试的修改冒充修复前后的独立证据。

路径策略允许 `.github`、依赖清单、构建配置和其他文本文件，并允许 `.gitignore`、`.editorconfig`、ESLint/Prettier 等常见构建点文件；继续拒绝绝对路径、穿越、链接、大小写别名、凭据路径、`.git`、运行数据和生成目录。未开放的隐藏路径仍受保护。仓库归档大小、内存包大小、路径结构和单次供应商输出上限属于资源/协议边界，仍然存在。补丁操作仍是创建或替换文件，未增加删除、二进制或文件模式变更操作。

保留不可变 original、新回归的 baseline、完整 candidate，并增加把原测试放回候选实现的 compatibility 副本。保存原套件、原测试对候选实现、新回归修复前后及候选完整套件的实际结果。原测试因授权契约变化而失败时必须由独立审查解释；不把“修改后的测试通过”作为唯一证据。

独立审查输出 `test_changes`：逐一列出被修改的既有测试及 `conftest.py` 路径与理由；原测试对候选实现失败时还必须返回 `original_suite_rationale` 解释具体失败与授权契约。批准缺少完整说明时后端拒绝记录批准。独立新增回归须修复前失败、修复后通过，候选全套测试仍须通过。

自身维护取消 Python 文件白名单；额外在独立的 Python/Node 容器中分别对原始和候选版本执行 Python 编译与 Ruff、`npm ci` 和前端构建，并将结果提供给审查角色。候选版本必须通过；原始构建或静态检查失败保留实际记录，安装失败明确标记检查未执行，独立审查须以 `baseline_rationale` 解释原始异常，避免以原构建失败阻止修复构建缺陷。Python 测试和前端构建不能证明 GitHub Actions 在远程已运行、浏览器交互或任意第三方语言正确；这些仍须实际 CI/专项验收证据。扩大可编辑范围不等同于所有技术栈均已完成自动验收。
