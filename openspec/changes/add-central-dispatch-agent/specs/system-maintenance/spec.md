# Spec Delta

## Purpose

将不能通过既有运行恢复解决的 RepoWatch 自身缺陷转成有证据、可去重且符合仓库规定的维护工作，复用修复与独立审查能力，产出可审阅的中文 Issue 和 PR，同时避免误改被分析仓库或重复发布内容。

## ADDED Requirements

### Requirement: 区分系统缺陷与目标仓库缺陷

系统 SHALL 仅在证据指向 RepoWatch 实现或兼容性问题时创建自身维护任务，明确绑定维护仓库和失败来源；外部服务暂时不可用、目标项目行为失败及未知原因分别保留对应分类，禁止自动伪造用户已确认的新缺陷。

#### Scenario: 系统工具批次处理不兼容
- **WHEN** 调用记录与实现共同证明 RepoWatch 对可合法处理的工具批次缺少恢复支持
- **THEN** 维护任务指向 RepoWatch，并关联受影响的目标仓库任务作为证据，不向目标仓库提交该内部缺陷

#### Scenario: 证据不足
- **WHEN** 只能确认模型超时，无法确认 RepoWatch 存在代码缺陷
- **THEN** 记录运行故障并继续允许范围内的诊断，不据此断定需要修改 RepoWatch 源码

### Requirement: 中文 Issue 与相似工作去重

系统 SHALL 在远程写入前核对当前 GitHub 身份为 `Gwex323`、仓库与授权范围，搜索相关 Issue/PR 并记录匹配依据；已有对应工作时补充关联证据，否则先创建说明问题、影响和预期行为的中文 Issue。远程结果未知时先核对再重试。

#### Scenario: 已有对应 Issue 和 PR
- **WHEN** 相同根因已有未完成的中文 Issue 和相关 PR
- **THEN** 复用并补充可验证证据，不因错误文本相似而关联无关 PR，也不重复创建工作

#### Scenario: 首次登记系统缺陷
- **WHEN** 没有相应工作且维护权限已启用
- **THEN** 以已核验账号创建中文 Issue 并保存远程编号，在 Issue 可核验前不开始源码修改

#### Scenario: 账号不符
- **WHEN** 当前远程身份不是 `Gwex323` 或仓库权限不足
- **THEN** 暂停远程写入并显示具体缺失条件，不切换为其他账号提交

### Requirement: 在隔离的合规分支修复

系统 MUST 在已有对应 Issue 后，从维护仓库最新实际默认分支创建 `feature/` 分支，并在隔离工作区修改；禁止直接改主干、使用 `codex/` 新分支、污染运行目录或覆盖其他未提交修改。

#### Scenario: 创建自身修复任务
- **WHEN** 对应 Issue 已登记且源码修复获授权
- **THEN** 记录默认分支与基础提交，在独立 `feature/` 工作区执行修复并保留补丁和验证记录

#### Scenario: 对应分支已经存在
- **WHEN** 相同维护任务已有合法分支与补丁
- **THEN** 核对任务关联及基础版本后续办，不新建重复分支或覆盖其他任务工作

### Requirement: 独立审查通过后创建中文 PR

系统 MUST 对实际补丁执行相关验证并由独立审查角色审查，通过前不得创建 PR；通过后 PR 标题和描述均使用中文，包含对应 Issue 及概述、变更内容、设计方案/说明、验证/验收、review 记录。

#### Scenario: 审查拒绝
- **WHEN** 独立审查指出覆盖不完整或补丁有问题
- **THEN** 在原任务预算内反馈修复并重新验证和审查，保留拒绝结论，不创建 PR

#### Scenario: 验证与审查通过
- **WHEN** 当前提交的相关验证和独立审查均通过
- **THEN** 在对应分支创建或更新中文 PR，关联 Issue、验证证据和 review 记录；后续补丁变化使旧审查失效

### Requirement: 发布结果与原故障关联

系统 SHALL 保留维护任务、源码提交、Issue、PR、审查和部署记录的关联；PR 创建或合并本身不得把原故障标记已恢复，只有修复版本上线后原失败检查验证通过才能关闭恢复链路。

#### Scenario: PR 已合并但尚未部署
- **WHEN** 自身修复 PR 在 GitHub 合并完成
- **THEN** 展示等待部署状态，原故障不显示已经恢复

#### Scenario: 新版本验证失败
- **WHEN** 修复部署后同一失败步骤仍失败
- **THEN** 将新证据追加到原维护链路，在原预算与授权内继续处理，不伪造验收通过或重复提交无关 Issue
