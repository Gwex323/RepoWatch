# Design

## Context

动机和范围见 [proposal.md](proposal.md)。提案建立时仓库只有需求／架构／研究文档，没有可继承的产品实现、数据库或测试基线；现已开始 P0，实际进度以 [tasks](tasks.md) 为准，OpenSpec 主规格仍为空。既定设计已在 2026-11-03 复核；[实施契约](../../../docs/implementation-contracts.md)是细化依据，11 份 `specs/*/spec.md` 是本变更的可验收行为合同。

硬约束包括：本地单用户、Windows 支持、全局串行、每次导入完整扫描、受控补全、执行障碍全局暂停、人工恢复、模型 API 多供应商、独审和证据门槛、分仓及去敏共享记忆。接口及工具版本仍需 P0 实验，不能由文档完整推断运行兼容。

## Goals / Non-Goals

**Goals:**

- 让业务状态、执行进度、实际代码和远端结果能够核对，节点成功不自动等于业务成功。
- 让模型和工具在同一有界执行权下工作，扫描、修复、返修及提炼共用最终控制层。
- 让全部最终能力从 P0 起有稳定接口与归属，后续阶段增加模块实现而不另起架构。
- 让失败、等待、取消、异常恢复、版本过期和 PR 未合并都具有明确处理路径。

**Non-Goals:**

- 不建设微服务、多用户权限体系或并行 Agent 集群，不依赖托管 MDA。
- 不在通用 Agent 容器中运行持凭据的发布器，不以提示词代替文件和命令权限。
- 不以扫描覆盖、模型结论或历史经验证明任意代码绝对正确，不以本次规划宣告实验通过。
- 多语言适配保持可扩展，首批落实 Python 与 JS／TS Web／CLI；专用硬件和无法获得的私有服务不作无条件支持承诺。

## Decisions

### 1. Modular monolith and module boundaries

沿用 Python 3.12＋FastAPI、独立 Worker、React／TypeScript／Vite。采用一个仓库、一个 API 进程和一个 Worker；只读同步循环由 API 生命周期管理，模型和仓库命令只由 Worker 发起。相较微服务，这减少本地部署负担；相较请求内后台任务，它提供独立执行和持久交接。

最终目录布局如下；P0 已建立工程入口及部分原型，其余模块按阶段落实：

```text
backend/
  pyproject.toml
  src/repowatch/
    domain/            # 对象、状态与规则，不依赖 SDK 或 ORM
    application/       # 扫描、修复、分诊、发布、记忆等用例
    api/               # 配置、操作、视图、事件、只读同步生命周期
    worker/            # 领取、心跳、运行派发、恢复
    runtime/           # LangGraph／Deep Agents 适配
    adapters/          # storage、github、models、git、docker、secrets、embedding
    operations/        # 启停、诊断、迁移、备份、清理
  migrations/
  tests/               # 单元、契约、集成和故障夹具
frontend/              # 仓库、任务、扫描、PR、供应商、记忆与系统页面
experiments/           # E1—E20 可复现实验入口及夹具定义
```

计划采用 uv 管理 Python、pnpm 管理前端，SQLAlchemy 2＋Alembic 承载业务数据与迁移，pytest 和 Playwright 分别验证后端及必要浏览器路径。这些是实现细节选择；P0 验证并锁定兼容依赖，不将研究快照直接当作已解析的锁文件。既定 LangGraph／Deep Agents 路线不因工具安装问题被静默替换。

### 2. Business records as the authority

业务库默认 `business.sqlite3`，图检查点使用独立 `checkpoints.sqlite3`，大产物在受管归档中；都由同一宿主侧进程访问。分文件隔离第三方迁移，但不假定跨库事务。保留存储端口及 PostgreSQL 适配边界，不在首版本额外部署 PostgreSQL。相比仅把全部状态塞进图状态，此方案能独立表达仓库、任务和 PR 生命周期。

| 记录 | 关键内容与约束 |
| --- | --- |
| Repository | GitHub 稳定 ID、上游／发布身份、目标／准入策略修订、三种模式及标签／严重程度映射、执行身份、认领评论开关／模板、导入代次、扫描策略、完整就绪标识、暂停／巡检配置 |
| Task | 来源唯一键、任务状态／阶段、等待原因、输入／反馈修订、人工排除标记、批准修订、预算归属及累计值；同仓同 Issue 一个主任务 |
| TriageDecision／QueuePriority | 六类结果、证据、输入／准入策略修订、标签／assignee／占用及重新分诊条件；人工优先级、自动严重程度、累计可执行排队时长及老化修订 |
| ProgressAttempt／ProgressState | 阶段目标、归一化动作、代码／输入／环境／策略修订、失败签名、有效证据差异／水位、连续无进展与振荡窗口；跨运行保留 |
| BudgetLedger／BudgetRenewal | 原授权、各维累计／预留及未知占用、有限追加、账本修订、单一续期提案、进度／输入快照、批准依据及幂等操作 |
| Run | 模式、代码／配置快照、执行代次、图线程、父／恢复运行、领取的信号集合／水位、起止及有意挂起原因 |
| GlobalControl／ExecutionLease | 全局状态、未解决阻塞原因、唯一执行者、递增代次、租期和心跳 |
| ScanBatch／CoverageItem | 固定 SHA、清单／策略版本、父覆盖来源、路径／内容标识、分块、真实结果及排除依据 |
| Candidate | 本地缺陷位置、版本、依据、选择状态及 Issue 查重／创建操作和关联任务 |
| Artifact／Validation／Review | 内容摘要、实际候选树、探针、命令／环境、日志、基线比较和独审发现 |
| PublishOperation／PullRequest | 稳定操作键、预期与实际远端身份／版本、待确认结果、PR 交付状态；Issue ID 与受管 PR ID 双向生命周期唯一，外部 PR 为独立观测 |
| Provider／RoleBinding／CapabilityCheck | 脱敏配置、凭据引用／修订、角色选择、能力结果有效范围 |
| RemoteObject／PendingSignal／SyncCursor | 远端稳定标识、内容修订、待分诊／返修信号、分页验证器及已完成水位 |
| Memory／IndexEvent | 正文／范围／修订、验证及反馈状态、来源、禁用／删除标记、待索引事件 |
| BusinessEvent／UserOperation | 可重读事件、人工操作标识、预期版本、结果与审计来源 |

创建任务、写待处理信号和业务事件采用同一业务事务；记忆事实更新与待索引事件同事务。产物先写临时位置，完整落盘并计算摘要后登记。图阶段使用“阶段意图→执行→业务结果／产物→检查点”的可核对协议；任一窗口中断都核对事实，不按图位置盲目重放命令或发布。

重导入按稳定仓库身份增加导入请求，不复制主任务／记忆范围。人工排除／取消在重导入和新信号后仍有效，明确重新启用才继续；已关闭交付链按原终态处理。依赖创建与父任务等待、扫描完成与依赖唤醒均通过业务事务衔接；取消非预算归属等待方只解除其依赖，撤销预算授权则安全停止扫描并保留其他依赖供人工处理，不自动转移成本。

### 3. Single execution lease and bounded state transitions

领取在短事务中检查全局／仓库状态、任务前置条件及唯一执行位，按人工优先级、自动严重程度／老化、原入队时间和稳定 ID 选择可执行任务；等待任务不堵住队首且不累计老化时间，不抢占执行中任务。写入拥有者和递增执行代次，心跳在独立短事务中续约，模型或命令运行不占数据库写事务。

工具入口、结果回写和发布前均校验代次。租约过期停止新操作，但不能据此接管旧命令；失去执行权、取消和暂停先确认命令已停止／隔离，再释放工作区。相比自动重领过期任务，人工对账降低双执行风险，接受恢复需要用户介入。

业务状态采用排队、执行、正常等待、阻塞、结束／取消；等待原因至少区分批准、澄清、耗尽前预算续期、扫描、CI 和评审。安全等待的运行记录有意退出／挂起，不能仅因存在检查点或开放 PR 判定崩溃。异常恢复复用有效阶段时核对输入、配置、代码与产物；保持原运行快照时才使用对应图线程恢复，新配置或实质输入变化建立新运行，不强行重放旧图上下文。

预算是主任务的累计账本，不是每个 Run 的默认额度。请求前预留调用／token 上限，结果返回后核对实际用量；未知用量保留保守占用。SDK 隐含重试关闭或纳入同一计量包装。等待不计有效执行时长，拆分、子任务、重建、返修和提炼继续计数。有实质进展且预计额度不足时，耗尽前在安全边界申请有限续期并正常等待；用户批准只增加授权总额，不重置累计值或独立安全上限。任一适用授权已耗尽仍阻塞并全局暂停，批准额度不自动恢复。

Worker 在工具／检查返回及阶段交接时按目标核验真实覆盖、实验反证和验证成果，持久化进展及比较窗口；不同模式共享检测端口，各用相应证据。连续无进展、振荡、超时和安全上限由程序决定，不能靠改日志、代码、SHA、Run 或续期清零。正常等待和未超时长检查不误计，模型自述不算证据。初值、指纹及恢复边界见[无进展契约](../../../docs/implementation-contracts.md#无进展检测)。

续期提案由已有产物形成并绑定账本／输入／进度修订，展示剩余目标、继续策略、各维有限增量及估计不确定性；同一修订只保留一个待处理提案，批准原子去重、过期拒绝。未批准不超额执行，估算模型也需授权，无可用额度则用持久记录；方案范围改变先重新批准，无进展阻塞另需实质处理和有界重试。UI 的预警、正常续期、耗尽阻塞分开显示，权威规则见[续期契约](../../../docs/implementation-contracts.md#进度驱动的预算续期)。

扫描／维护 Task 可独立调度，但预算归属必须固定。修复新建的前置补扫归原修复账本；共享已有扫描保留其原归属，不重计、不转移；导入漂移仍归原导入。诊断有单独的有限预算，不重置业务额度。扫描执行期间的实际消耗计入归属账本，不能因父任务显示等待而漏记。

暂停时 API、只读同步和人工管理继续。用户可明确发起独占、有界的诊断运行验证新模型配置；诊断没有业务代码写入与发布工具，结果不清除全局阻塞原因。

### 4. Workspace snapshots and execution capabilities

宿主使用受管 Git 配置维护无检出对象副本，clone／fetch 不执行仓库脚本或过滤器；令牌不写 remote URL 或持久仓库配置。通过受控对象／bundle 交接在 Linux 容器卷中物化工作树，任务容器不接触宿主凭据。候选冻结为提交／树和实际内容清单，导出 Git 对象后由发布器核对再推送。

物化清单包括换行、大小写、可执行位、链接、子模块 SHA 和 LFS 内容映射；LFS 指针不等于真实受检内容。P0 验证 Windows 裸对象存储到 Linux 工作树再回到发布对象的一致性，避免直接使用宿主日常 checkout 带来的内容变化。无法保证映射时阻塞，不把本机一次命令成功当作一致性证明。

bundle 外的 LFS 实体和子模块对象单独核对可得性；发布时也须保证接收方可取得引用内容。缺少受控 LFS 上传适配或子模块提交尚未发布时阻塞，不自动推送子仓库或执行持凭据 hooks；相关交付边界见实施契约 §6。

工具能力按模式发放：扫描只读源码并可写独立分析目录；实现写当前任务；最终 Runner 在冻结候选副本执行；独审只读并可申请 Runner 检查；提炼只读取受控证据。默认后端不挂数据库、凭据库、证据归档写目录或 Docker socket。文件及归档引用均限制路径、链接和归属。

原生适配是显式开启的端口，不是退回同权限宿主 shell。它须通过隔离身份／文件权限等能力验收；不能保护凭据和控制接口时拒绝执行并解释不支持条件。该取舍优先保持凭据边界，不能声称所有宿主专用项目都可自动处理。

### 5. Runtime composition and model protocols

LangGraph 管阶段、持久进度和中断，Deep Agents 管模式内工具循环。只使用本地／同步子任务，不接入托管异步路径。处理与独审使用不同会话、工具集和可选供应商；独审由工作流必经派发，不由处理角色自行选择。

运行适配层接收版本化任务信封，包含 task／run、输入／规范修订、代码、配置、预算、工具策略、记忆引用，输出结构化结果和产物引用。失败结构不合法可在预算内修正；不能把自由文本直接映射到完成。子任务共享父预算，父模型等待子任务期间不并行调用或写工作区。

供应商交互遵循既定参考格式：手工或 JSON 单个／数组／providers 包装，整批新增、不覆盖、不部分提交。协议端口区分 Chat Completions 和 Responses，允许自定义地址与手填模型；基础连接、列表和角色能力检查分开。先检测处理与独审角色的真实工具和结构化交接，再投入修复。

整批新增的原子性是用户可见的配置激活原子性：业务操作记录关联暂存凭据，全部就绪后一次激活，重启对账未激活引用。keyring 与 SQLite 不共用事务；导入失败不能留下可用半批配置或修改旧凭据。

运行快照记录配置及凭据修订引用；缓存能力结果还绑定模型、接口、适配器、工具协议和有效期。密钥轮换失败进入阻塞，用户明确选择新快照后恢复。瞬时错误有限重试，不自动跨供应商切换。与仅判断“HTTP 成功”相比，此方案增加探测成本，但能在修改前发现关键不兼容。

### 6. Scan coverage and prerequisite scheduling

导入创建完整扫描任务，按固定提交生成清单、排除记录、检查策略和模块／分块。适用基线记录通过、已有失败、有依据不适用和无法执行。模块输入与结果、基线和候选证据共同参与程序核验；结果只证明约定覆盖，不证明发现全部 Bug。用户选择本地候选后，系统完整查询相似 Issue；匹配时关联已有 Issue，确认未匹配时由系统创建 Issue，并在远端结果核实后再建立主任务。

缺口按类型补扫、拆分、重试、重收证据或重建受管环境，保持原预算与扫描执行位，不修改业务源码／锁文件。新目标 SHA 创建新批次，可靠影响分析可复用有明确来源的旧项，其他内容重审；影响无法确定全仓重扫。同批次不修改 SHA。重新导入总是完整扫描。

所有修复入口核对 `(repository_id, target_config_rev, import_epoch, target_sha, scan_policy_rev)` 的完整就绪标识，不能只检查 SHA。新的导入请求原子撤销旧就绪并增加代次，即使目标 SHA 不变也须完成本次全仓扫描；旧代次结果不能重新放行。策略变化和环境／工具变化按实施契约 §4 撤销或复核相关依据。改目标分支不静默改投已有任务／PR。

未合并 PR 修改由任务验证覆盖，不改变目标分支就绪。发布前发现版本或导入就绪条件变化，修复保存并进入扫描等待、释放执行位；创建／关联前置扫描工作，完成后整合新 base 再重验重审，避免唯一执行位死锁。导入中漂移与拆分不重置其累计预算。

### 7. Verification, publication and feedback

分诊入口采用版本化仓库三模式，默认值、排除及六类结果以[准入契约](../../../docs/implementation-contracts.md#issue-准入与分诊)为准；输入不足／敏感处理属于 UI 正常等待，正式复现失败等执行障碍仍全局阻塞。本地占用不赋予 GitHub 独占，建分支前及发布前重查标签、assignee、占用和相关 PR。默认不 assign／评论；显式启用的认领评论由宿主发布适配器以独立操作意图、预期版本和回执对账执行，不放给同步循环或 Agent。

发布采用 [Issue／受管 PR 一一对应](../../../docs/implementation-contracts.md#issue-与-pr-一一对应)：双方稳定身份双向唯一，创建前先持久占用唯一发布意图、结果未知先对账，关闭后不释放绑定；返修原 PR，不按模块拆 PR 或合并独立 Issue。外部 PR 可有多条事实观测，不认领为受管交付，也不替换原绑定；多目标 Issue 先经 UI 确认范围处理。

流程为待分诊信号／用户选择本地候选→取得执行位→模型分诊／方案。对本地候选，系统先完整查询相似 Issue，关联同一问题或在确认无相似项后创建 Issue；Issue 写入回执未知时先对账。所有任务在创建修复分支前检查 Issue 的开放 PR；同一问题的外部 PR 关联并等待、确认无关则继续，仅关系不明通过 UI 请求用户决定，发布前再次分类。相关 PR 已合入目标分支时直接重取有效扫描／复现证据，确认解决则记录外部修复解决，否则重核剩余范围后基于最新版本继续。修复阶段重新按扫描就绪条件领取→能力与版本预检→检索经验→创建修复分支→修改前证据→修改→冻结候选→Runner 基线／修改后验证→独立只读审查→当前证据门槛→受控发布。Bug 使用同一探针证明前失败后通过，探针在 base 副本不夹带实现；功能和纯重构使用批准规范，行为保持和结构目标分开验收。

返修区分上游 base、返修前 PR head 和新候选：原 Bug 的失败侧是未修复上游，新评审缺陷才可能以旧 PR head 为失败侧；格式意见不要求伪造失败。最终仍审查完整 PR 相对当前 base 的改动及回归，不能只验本轮增量。

比较基线时检查失败用例及原因、发现数量、skip、断言与命令变化，不只比较退出码或失败总数。未执行到目标断言的缺包／超时不能算复现。可修复问题在原预算内返回实现；无法归因、无法验证或耗尽预算则阻塞。

发布器在宿主持 GitHub 写凭据，只处理冻结对象，不执行仓库 hooks／脚本。写操作记录稳定意图、原分支预期 SHA、候选 SHA、上游／发布仓库及 base／head。默认快进更新；外部更新先整合重验，不能盲目 force。创建／更新后核对实际 PR；回执丢失查询所有相关状态，未知保持阻塞。GitHub 没有通用创建幂等键，前后核对不能消除全部竞争窗口。

PR 正文使用既定五段结构并关联已确认的 GitHub Issue 及本地候选来源。提交前证据与 PR 专属 CI 分开，若唯一证明只能在 PR 环境产生且无替代有效证据，则不为触发 CI 而发布。等待 CI／评审释放执行位；新意见关联原任务和受评提交，范围内返修自动排队，范围变更先批准，预算不重置。

CI 汇总基于版本化必要检查集合、来源和最新适用 attempt；重跑 pending 不沿用旧成功，已被取代的旧失败不永久阻塞。skipped／neutral 等结论按显式策略处理；无关失败不直接触发返修。

验证通过事件同时保存待提炼意图；提炼以来源任务关联的串行模式执行，不给源码写权限，不作为另一个可跳过验证的发布依据。提炼失败不倒填成功，持续模型障碍仍按全局规则处理；已发生的有效验证／远端发布记录不被伪改。

### 8. Durable synchronization without model work

默认活跃间隔 2 小时、空闲 24 小时；后者按上次成功同步后的间隔计算，不额外假定每天某个固定时刻。活跃初值为存在未结束任务／受管 PR，或最近 7 天观测到 Issue／PR 更新；均可配置，PR／CI／评审使用同仓频率。定时之外仅首次、人工和发布前必要读取立即触发。

API 生命周期内同步循环持有独立同步租约。每端点／查询／页保存验证器，必要页可逐页 upsert，但完整查询落库后才推进高水位。使用重叠窗口和周期复核；304 需有可用的对应缓存状态，不能推断全部页无变化。评论、review、checks 和 statuses 按端点能力读取，不套用 Issue 的 since。

远端对象按稳定 ID、修订／载荷摘要更新；Issues 中 PR 分流。对象、待处理信号与事件原子保存，Worker 消费信号进行分诊或返修。Issue 编辑／关闭／重开更新输入修订，执行中不静默替换；发布前再次核对，关闭信号需联查合并状态。

运行只确认自己领取的信号 ID／修订，期间新增反馈留给后续运行；业务结果与确认同事务提交。同步和发布前读取均防止旧代次／旧对象覆盖新修订；无法排序的冲突重读。相同内容不增加输入版本，也不刷新最近变化时间，防止空闲仓库因重复轮询永久活跃。

纯同步网络／限流失败保留上次成功水位，显示健康及退避，不直接把所有任务判失败；任务必须取得的当前权限／状态不可核验才阻塞。重启合并错过的到期点执行一次补偿，不堆积定时回放。

### 9. Versioned memory and rebuildable indexes

业务记忆表保存正文、来源、范围、内容修订、验证、反馈与删除／禁用状态；原始大内容保留仓库归属归档。成功经验来源于验证＋独审，失败分开，根因假设仍标推测。跨仓只提供经验证、去敏且允许共享的模式／方法，无法确认去敏则留在仓库范围。

采用业务服务提供记忆读写与工具，不把默认框架 Store 当作可直接写业务状态的授权通道。可复用已存在的 SQLite Store 原语作为适配，但不能另建一份独立正文事实源。相较无过滤的全局向量库，这保留仓库边界和删除语义。

FTS5＋sqlite-vec 是可重建派生索引。初始搜索文本对代码标识符作规范化拆分，并评测中文词／字符片段预处理；文档与查询使用同版本规则。本地 CPU 编码优先评估 FastEmbed 适配，具体编码模型由 P0／P5 的许可证、中文／代码召回和资源实验选择，资产下载需明确配置。语义不可用明确降级。

检索先按范围及状态限定候选，关键词／向量各取有界候选后融合排序，再回源核验修订并限制注入量。初始融合可采用倒数排名融合，不以原始不同量纲分数直接相加；候选数、融合参数和上下文上限在评测后配置，不作为硬编码产品要求。

记忆事实和 IndexEvent 同事务，索引项记录内容／编码版本，滞后项回源剔除；换模型重建核验后切换。新 CI 失败／请求修改先把关联经验设为反馈待判断，暂停成功复用，再由 Worker 判断是否反证。语义编辑不沿用旧成功标签；禁用／删除先影响事实源，新注入和恢复 checkpoint 时重新核验独立记忆注入块。任务审计产物及已发送模型请求有独立留存，不宣称删除记忆能撤回历史。

来源证据保存反馈修订，即使记忆未建也不能漏掉反证；提炼／复核写入比较来源、反馈及记忆修订，迟到结果不能恢复被编辑／删除的版本或其共享派生项。每次模型请求前检查记忆依赖，摘要和压缩缓存也须可追溯、可移除；无法拆除时从当前有效事实重建会话，不重放污染摘要。具体边界见实施契约 §9。

### 10. API, UI and local access

采用 `/api/v1`，长任务请求返回持久操作／任务标识及 202，配置读取与视图返回 200；参数无效和状态／版本冲突分别返回明确校验／冲突结果。人工变更带操作标识和预期记录修订，重复请求返回同一结果，防止双击恢复或重复创建。

操作标识还绑定请求内容摘要：相同标识但不同内容返回冲突，不返回上一操作成功结果。正文和日志不保存密钥；摘要／凭据引用的处理须保持脱敏边界。

| 接口组 | 计划操作 |
| --- | --- |
| repositories | 导入、读取、目标／巡检／准入策略配置、标签／严重程度及认领评论配置、手动检查更新、暂停、Issue／候选选择 |
| tasks／runs | 列表、详情、六类分诊／占用／老化依据、待人工事项、优先级、排除／取消／明确启用、方案／范围批准、补充材料、重新分诊、关系判定、阻塞核对及恢复请求 |
| providers／roles | 原子导入、编辑、脱敏读取、显式列表／能力诊断、角色模型绑定 |
| pull-requests | 交付、CI／评审、对应提交、返修及远端待对账视图 |
| memories | 来源、范围、状态、检索、纠错、禁用／删除和索引状态 |
| system／events | 全局暂停、诊断、健康、预算／日志、启停与备份状态、按游标读取事件 |

生产前端由 API 同源提供静态资源，事件使用可恢复 SSE 加业务状态回源，SSE 不承载任务执行。UI 页面映射 11 个能力，P1 提供最小控制、待人工事项和故障处理框架，各阶段引入能力时同步交付其人工入口，P6 完成产品化，避免直到末期才具备人工恢复操作。

每项人工事项关联稳定对象与修订，记录原因、证据、允许动作、输入、前置条件和结果；集中待办与详情页互相跳转，暂停时仍可处理，刷新可回读。具体类别和动作以[实施契约 §3](../../../docs/implementation-contracts.md#人工处理入口与操作)为权威映射，CI／评审／合并提供 GitHub 跳转。提交后按预期修订重核，过期决定报冲突；异步核验显示实际状态，模型／命令仍由 Worker 调度。补充材料、改配置、诊断、预算调整不自动恢复；显式恢复必须核对全部未解决原因，UI 不提供忽略证据门槛的强制通过。

P4 仓库“检查更新”触发只读同步并展示读取与扫描状态；定时、启动补偿和人工同步读取目标分支 REST branch 的 `commit.sha`，按配置版本比较并登记版本漂移。缓存验证器、并发去重、失败和暂停边界遵循实施契约 §7；修复前／发布前仍独立核验远端 SHA。

默认回环监听，本地会话使用受控启动引导建立，变更请求校验会话和来源，开发 CORS 仅允许指定来源。凭据存宿主 keyring／受保护存储；读取 API、事件、错误和日志都脱敏。仓库任务既没有本地会话，也不获得管理接口能力。

### 11. Operations and stage gates

宿主 API／Worker 统一在 Windows；若提供 WSL 宿主配置，两者与数据库一起迁入，不能跨侧共享 WAL。默认 WAL、短事务、连接外键及有限锁等待。迁移由唯一进程在服务停写时执行；正常停止先停领取、清理旧命令并记录安全挂起。

备份使用一致性接口／停写和统一产物清单，不能只复制活跃主文件遗漏 WAL。恢复先暂停并核对远端与工作区；空间不足或业务状态不可持久化时停止新执行和发布。保留策略不自动删除活动／阻塞任务所需内容，删除历史归档更新引用可用性。

默认备份以统一维护屏障暂停所有相关写者，包括 API／同步落库、Worker／checkpoint、索引和清理；固定同一组数据库与产物后才标记备份有效，退出时保留先前暂停状态。单库 backup API 不是跨库一致快照，恢复另行核验凭据引用。最小存储失败拒绝执行／发布和安全停止随 P1 实现，P6 才补充完整运维界面。

| 阶段 | 前置与退出条件 |
| --- | --- |
| P0 | 锁定兼容依赖与最小字段／协议；完成 E1、E7、E8、E11、E13、E18 的关键切片；无法满足硬约束则先调整适配并重估 |
| P1 | P0 通过；持久队列、状态／预算、凭据／模型、共享运行引擎、最小界面及读取接口就绪，存储失败拒绝执行和安全停止已生效；E7、E14、E18 及 E20 内核／凭据切片可重复 |
| P2 | P1；仓库工作区与通用 Runner 先就绪，再接完整扫描、缺口补全和版本补扫；E2、E3 及扫描部分 E15 通过 |
| P3 | P2；有效修改前后、独审、冻结候选、首条直接／Fork 发布与对账；E4—E6、E9、E15、E19 通过 |
| P4 | P3；完整巡检、评审返修与终态；E13、E17 和真实测试仓库链路通过 |
| P5 | P4；自动提炼、混合索引、反馈纠错及人工管理完整；E10、E12、E16 有结果，收益不预先承诺 |
| P6 | P5；最终 UI、启停升级备份清理与 Windows 全链路；E11、E20 和关键回归通过 |

## Risks / Trade-offs

- [SQLite 单写及两进程竞争] → 短事务、独立心跳、派生索引批处理及 E7／E20；不把 SQLite saver 存在当负载保证。
- [图进度与业务库／外部操作非原子] → 阶段意图、不可变产物、执行代次和对账；不盲目重放远端动作。
- [模型语义判断不稳定] → 有效复现、真实 Runner、独立审查和拒绝证据不足发布；自动解决率须由真实样本测量。
- [每次导入全仓扫描占位且成本增长] → 分块、缓存有效产物及受控补全，预算对用户可见；不能缩减覆盖隐藏成本。
- [目标分支持续变化] → 扫描依赖与候选重验，累计预算防无限追赶；必要时人工处理。
- [Windows／Linux Git 内容不一致] → P0 验证对象交接和物化清单，未通过不继续扩大实现。
- [供应商工具协议或密钥变化] → 能力准入、快照和有界诊断，无自动跨供应商回退。
- [历史经验误导与共享泄露] → 来源／范围／去敏、反馈待判断、状态回查和当前仓库独立验证。
- [原生适配隔离不足] → 只有显式启用且通过能力验收才执行，否则阻塞；通用容器路径仍是默认。
- [16—24 人周估算偏低] → 仅沿用核心闭环与首批适配的低精度估算，P0 后依据失败实验和恢复成本重估，不承诺任意语言均在此范围内。

## Migration Plan

1. 提案阶段新增本变更规划，既有需求／研究文档保留；实施阶段按任务记录证据，主规格在变更完成验收并归档前不提前同步为已实现。
2. 实施 P0 后建立依赖锁、数据库首版迁移及最小协议；P1 起通过同一数据／状态模型逐步启用能力，未通过阶段门槛不开放相应自动交付路径。
3. 最终部署提供前端静态资源、单 API、单 Worker、宿主凭据配置与 Docker／WSL2 检测，浏览器关闭不停止服务。
4. 升级前停写并一致备份，唯一迁移者执行版本检查；失败时停服务并恢复匹配的数据库、图状态和产物清单，核对 GitHub 后由用户恢复。远端写入不能被本地回滚撤销，禁止恢复旧备份后直接重发。

## Open Questions

- 本地编码模型及版本的最终选择：在固定的 CPU、离线、中文／代码和许可边界内按 P0／P5 实验确定，不改变混合检索及事实源接口。
- 心跳／租期、请求超时、候选数量和日志保留初值：根据同机实验校准，保持唯一执行位、有限预算和人工恢复语义。
- 实际供应商／模型、目标样本及私有依赖可得性：实施时由配置提供并记录结果；不可用明确阻塞，不缩减门槛或假设已经兼容。
