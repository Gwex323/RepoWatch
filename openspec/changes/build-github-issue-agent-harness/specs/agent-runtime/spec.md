# Spec Delta

## Purpose

为扫描、调查、规划、复现、实现和记忆提炼提供共享处理执行能力，同时以独立会话和真实权限隔离审查角色，使 Agent 在有界任务内自主工作，流程状态与最终交付仍由程序证据规则掌握。

## ADDED Requirements

### Requirement: 保持两类核心角色及任务模式

系统 SHALL 提供处理与独立审查两类核心角色，将扫描、调查、规划、复现、实现和提炼作为处理任务模式，不要求为每阶段新增固定常驻 Agent。

#### Scenario: 任务需要扫描或复现
- **WHEN** 工作流派发对应模式
- **THEN** 处理引擎获得该模式的输入及限定工具，并继续受同一执行位和预算约束

### Requirement: 阶段转换由程序化工作流控制

系统 SHALL 依据结构化结果、实际产物和验收规则推进阶段；Agent 自述完成不能直接设置扫描完成、验证通过或 PR 已创建状态。

#### Scenario: Agent 声称修复完成但证据缺失
- **WHEN** 返回消息没有有效验证产物
- **THEN** 系统维持待验证阶段，不授予发布权限

### Requirement: 角色交接携带可追踪任务上下文

系统 SHALL 通过 Harness 交接任务与结果，携带主任务／运行标识、输入及验收版本、代码版本、配置快照、预算和产物引用，并校验结构与归属。

#### Scenario: 子任务返回错误运行的产物
- **WHEN** 结果引用不属于当前授权任务或代码版本
- **THEN** 系统拒绝使用该结果推进当前阶段

### Requirement: 子任务默认串行且单工作区单写

系统 SHALL 在需要时委派受管子任务，默认串行并共享原任务预算；父任务等待子任务时不得继续并发模型调用或写同一工作区。

#### Scenario: 实现期间委派调查
- **WHEN** 处理角色申请子任务
- **THEN** 系统限定子任务输入／工具、暂停父模型执行，完成交接后再继续父任务

### Requirement: 独立审查是发布前必经阶段

系统 SHALL 为候选启动与处理会话分离的只读审查，授予需求、Diff 和真实证据访问，不授予发布、源码写入或验收记录修改能力；处理角色不能自行取消该阶段。

#### Scenario: 处理角色请求直接发布
- **WHEN** 当前候选尚无有效独审结论
- **THEN** 系统拒绝发布并安排独审

#### Scenario: 独审需要补充运行检查
- **WHEN** 审查提出有依据的检查请求
- **THEN** 系统由受控执行器在临时环境运行并提供证据，不开放审查的通用写终端

### Requirement: 运行进度和业务完成分层管理

系统 SHALL 保存可恢复的内部执行进度，并以业务记录和有效产物决定对外状态；恢复时核对执行权、代码、输入、配置及记忆可用性，不盲目重放副作用。

#### Scenario: 检查点比业务记录超前
- **WHEN** 恢复发现节点已运行但产物或远端结果尚未确认
- **THEN** 系统先对账，不仅凭节点位置宣布任务通过或重发发布操作

#### Scenario: 运行内部摘要包含失效记忆
- **WHEN** 下一次模型请求前依赖核验发现摘要含已禁用经验
- **THEN** 运行适配层移除对应内容或重建干净会话，框架压缩／检查点恢复不得绕过记忆可用性规则
