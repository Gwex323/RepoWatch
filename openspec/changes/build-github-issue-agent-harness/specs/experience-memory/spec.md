# Spec Delta

## Purpose

把真实修复与失败尝试转为有来源、可纠错的任务经验，在保留仓库边界的前提下支持同仓和跨仓相似问题检索，并确保失效、删除、索引滞后或后续反证不会把旧经验误当成当前修复证据。

## ADDED Requirements

### Requirement: 记忆保存正文来源范围和验证状态

系统 SHALL 保存问题特征、适用范围、方法、验证方式及来源任务／运行／代码／证据，区分成功、失败、待复核和人工未验证状态；大型代码、日志和历史按仓库归属保存引用。

#### Scenario: 查看一条成功经验
- **WHEN** 用户打开记忆详情
- **THEN** 用户可看到其适用条件、验证来源及代码版本，而非只有无依据的结论

### Requirement: 成功提炼依赖验证和独审

系统 SHALL 在修复通过验证与独审后自动提炼，单独记录 PR 接受／合并状态；扫描猜测和根因推测不得直接成为已验证结论，提炼调用计入来源任务预算且仅可读证据。

#### Scenario: PR 尚未合并但修复已验证
- **WHEN** 验证与独审通过
- **THEN** 系统可以提炼已验证修复经验，同时记录 PR 尚未被接受或合并

#### Scenario: 一次修复尝试失败
- **WHEN** 方法未完成有效修复
- **THEN** 系统单独保存失败方法、原因和依据，不把它作为成功解决方案

### Requirement: 跨仓只共享提炼去敏经验

系统 SHALL 保留仓库原始代码、日志和完整历史的范围，只向其他仓库提供允许共享的去敏问题模式、修复方法和验证经验；无法确认可共享时保留仓库范围。

#### Scenario: 仓库 B 检索仓库 A 的经验
- **WHEN** A 的原始上下文不在 B 可访问范围
- **THEN** 检索仅返回允许共享的提炼经验，不返回 A 的原始代码或日志

### Requirement: 检索先过滤再融合并回源核验

系统 SHALL 限定仓库／共享范围和可用状态后结合关键词与语义候选，融合排序并回查正文版本及状态，以有限上下文附来源注入；失败经验只作风险参考。

#### Scenario: 检索命中已禁用旧索引项
- **WHEN** 派生索引仍包含禁用或旧版本记录
- **THEN** 系统通过回源核验剔除，不将其注入新任务

#### Scenario: 命中相似仓库的成功经验
- **WHEN** 处理角色使用该经验提出修复方案
- **THEN** 当前仓库仍须独立复现、验证和审查，不能继承历史验收结果

### Requirement: 后续反馈暂缓并纠正成功复用

系统 SHALL 在关联提交收到新 CI 失败或请求修改时把经验标为反馈待判断并暂停成功复用，再由 Worker 判断关联性；反证成立待返修复核，无关或格式意见可恢复原状态。

#### Scenario: CI 推翻此前验证结论
- **WHEN** 反馈判断确认修复无效
- **THEN** 原成功经验停止成功复用，返修通过后形成有新证据的版本

#### Scenario: 新反证早于提炼结果落库
- **WHEN** 来源任务已收到新失败反馈，旧证据的提炼随后返回
- **THEN** 系统比较来源反馈修订，将结果保持待判断而非有效成功，其共享派生经验也不能绕过来源状态

#### Scenario: 反馈复核期间用户删除记忆
- **WHEN** 用户删除或语义修改了复核所针对的记忆版本
- **THEN** 迟到复核不得恢复旧版本或另建 ID 绕过删除，只有仍匹配的来源／反馈／记忆修订可更新

### Requirement: 人工修改禁用和删除影响后续使用

系统 SHALL 支持查看、纠错、禁用和删除，语义编辑不得自动继承旧验证标签；状态先在事实源生效，每次模型请求及 checkpoint 恢复复核记忆依赖，包括摘要／压缩缓存，不能重新发送已失效内容。

#### Scenario: 删除后恢复旧运行
- **WHEN** 运行检查点引用了已删除或禁用的记忆
- **THEN** 系统重建记忆注入并排除该记录，不把旧缓存重新当作有效经验

#### Scenario: 用户修改修复方法正文
- **WHEN** 编辑改变了原经验语义
- **THEN** 系统产生新版本并标明需要相应验证，不自动沿用原成功标签

#### Scenario: 被删除记忆已进入模型摘要
- **WHEN** 后续请求将使用含该经验的摘要或压缩上下文，且无法可靠拆除
- **THEN** 系统从当前任务输入及有效代码／证据重建会话，不把旧摘要作为普通背景重新发送；不声称撤回已发送请求

### Requirement: 派生索引可重建且允许明确降级

系统 SHALL 将记忆事实更新与待索引事件一同持久化，使用本地 CPU 编码并记录模型／维度／编码版本；换配置先重建核验再切换，语义不可用明确降级到关键词／范围检索。

#### Scenario: 更换本地编码模型
- **WHEN** 新模型维度或编码规则与旧配置不同
- **THEN** 系统重建新索引并核验，不混用旧向量

### Requirement: 删除范围与效果可被准确说明

系统 SHALL 区分记忆删除、派生缓存清理和原任务审计产物留存，不声称已撤回历史模型请求；记录复用来源与任务结果以评估收益，不仅以命中率宣称提效。

#### Scenario: 比较有无记忆的任务效果
- **WHEN** 在隔离的同仓／跨仓任务样本上进行对照
- **THEN** 系统报告验证通过率、时间和模型消耗，并避免预先写入当前答案造成评测泄漏
