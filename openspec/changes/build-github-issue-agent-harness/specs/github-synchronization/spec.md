# Spec Delta

## Purpose

持续同步 GitHub 已有和新增 Issue、受管 PR、评论、CI 与评审状态，在不执行模型或仓库代码的前提下形成持久待处理信号，并通过分页、去重、限流及补偿机制避免漏处理和重复修复。

## ADDED Requirements

### Requirement: 按仓库频率持续巡检

系统 SHALL 默认对活跃仓库约每 2 小时、空闲仓库每天同步一次，并允许按仓库配置；有未结束任务／受管 PR 或最近可配置回看期内有更新的仓库视为活跃，回看期初值为 7 天。

#### Scenario: 仓库存在开放受管 PR
- **WHEN** 仓库到达下次巡检时间
- **THEN** 系统按活跃频率同步 Issue、PR、CI 和评审，不暗中另设分钟级默认巡检

#### Scenario: 用户手动立即同步
- **WHEN** 用户明确发起同步或发布前需要最新读取
- **THEN** 系统执行必要读取，不要求等待下次定时点，同时遵守限流与同步去重

### Requirement: 同步检测目标分支版本

系统 SHALL 在定时、启动补偿及人工同步时通过 GitHub REST `GET /repos/{owner}/{repo}/branches/{branch}` 读取当前目标配置的 `commit.sha`，与已确认目标 SHA 和扫描就绪标识比较；验证器和对应 SHA 按仓库及目标配置修订隔离。304 仅在对应已确认 SHA 和配置有效时复用，否则无条件重读。修复开始前及发布前独立无条件读取当前 SHA。

#### Scenario: 目标分支发生变化
- **WHEN** 同步确认目标 SHA 与当前就绪版本不同
- **THEN** 系统持久化观测、撤销旧就绪并登记或关联新版本前置扫描，重复观测不产生重复活跃扫描

#### Scenario: 分支读取失败或结果过期
- **WHEN** 读取失败、响应缺少有效 SHA，或旧同步结果在目标配置变化后返回
- **THEN** 系统不报告无变化，不用旧结果覆盖当前配置；失败保留上次成功记录并退避，必要状态无法核验时按执行障碍处理

#### Scenario: 暂停期间手动检查更新
- **WHEN** 全局或仓库暂停期间用户发起检查，读取发现新 SHA
- **THEN** 只读同步保存变化并登记扫描，扫描等待相应恢复，不能旁路运行模型或仓库命令

#### Scenario: 反复读取相同载荷
- **WHEN** 没有未结束任务／受管 PR 的仓库持续返回相同对象内容
- **THEN** 系统不刷新最近变化时间，超过活跃回看期后允许转为空闲频率

### Requirement: 首次同步包含已有 Issue

系统 SHALL 在导入时同步已有 Issue，后续保存新增与更新对象并产生待分诊／返修信号；同步本身不得调用推理模型、运行仓库命令或发布远端内容。

#### Scenario: 全局暂停期间出现新 Bug
- **WHEN** 同步发现新的 GitHub Issue
- **THEN** 对象及待分析信号持久保存，模型分诊等待 Worker 恢复

### Requirement: 分页和端点分别管理进度

系统 SHALL 按端点、查询及分页保存验证器和水位，必要页面全部持久化后才推进水位；使用重叠窗口与周期复核，不能将单页 304 当作全仓无变化。

#### Scenario: 分页中途失败
- **WHEN** 一次查询部分页面成功而后续页面读取失败
- **THEN** 系统保留已落库对象但不越过缺页推进水位，后续重读按对象去重

#### Scenario: 评论端点不支持 Issue 的过滤参数
- **WHEN** 同步评论、评审或检查结果
- **THEN** 系统按该端点支持的分页和过滤读取，不套用 Issue 的 since 假设

### Requirement: 对象及反馈去重并正确分流

系统 SHALL 以仓库和 GitHub 对象稳定标识去重，将 Issues 列表中的 PR 分流，并把重复反馈关联原任务及受评提交，不创建重复活跃修复。

#### Scenario: Issues 响应中包含 PR
- **WHEN** 对象具有 PR 标识
- **THEN** 系统按 PR 同步处理，不将其作为普通 Bug Issue 自动修复

#### Scenario: 重复拉取同一请求修改
- **WHEN** 多次同步相同评审 ID 和版本
- **THEN** 原任务仅保留一份对应返修信号

### Requirement: 创建本地候选 Issue 前完成相似项查询

系统 SHALL 在用户选择本地缺陷候选并通过准入／敏感信息核验后，完整查询目标仓库的 Issue，并比较标题、正文、标签、位置／符号、目标 SHA 和候选证据等可用信息。确认同一问题时关联已有 Issue；只有查询完整且未发现相似项时才允许由系统创建 Issue。查询失败、分页缺失或语义无法判断时保留候选并等待核对。

#### Scenario: 完整查询未发现相似 Issue
- **WHEN** 目标仓库 Issue 查询的所有必要页面成功且没有候选相似项
- **THEN** 系统允许为该候选创建 Issue，并按远端稳定 Issue ID 幂等关联本地候选

#### Scenario: 查询分页失败
- **WHEN** 查重查询未能读取完所有必要页面
- **THEN** 系统不判定“无相似项”，不创建 Issue，并保留重试／核对状态

#### Scenario: 系统 Issue 写入重试
- **WHEN** Issue 创建响应丢失或 Worker 在写入后中断
- **THEN** 系统先按持久操作意图核对远端候选结果，确认前不再次创建

### Requirement: 信号消费和远端修订不会丢失新更新

系统 SHALL 原子提交对象、输入／反馈修订及待处理信号；运行仅确认领取的信号集合和修订，迟到读取不能覆盖新状态，不可排序的冲突须重读核对。

#### Scenario: 返修执行中到达第二条意见
- **WHEN** 运行领取首条意见后，同步保存了新的评审信号
- **THEN** 旧运行落库只确认已领取集合，新意见仍待处理，不按任务 ID 全部清空

#### Scenario: 旧请求晚于新观测返回
- **WHEN** 旧同步代次或较旧对象结果晚于已保存的新修订返回
- **THEN** 系统不回滚新状态；同时间戳冲突或缺少可排序版本时保留不确定性并重新读取

### Requirement: 更新输入时保留任务快照

系统 SHALL 记录 Issue 编辑、相关评论、关闭／重开、标签／assignee、准入策略、目标分支及验收范围变化并产生去重重新分诊信号，不静默替换执行中输入；模型分诊由 Worker 串行消费，暂停时不旁路运行。发布前复核有效需求和准入，关闭或实质范围变化的旧输入不得直接发布；目标 SHA 改变本身按补扫重验处理，目标与验收不变时不无故废弃方案批准。

#### Scenario: 修复中 Issue 被关闭
- **WHEN** 系统收到关闭状态
- **THEN** 系统核对相关 PR 是否已合并，再决定记录交付、停止未发布修改或等待澄清，不按同步顺序误判结果

#### Scenario: 补充评论或移除排除标签
- **WHEN** 相关新信息补齐待办，或策略形成的排除原因因标签／assignee 变化消失
- **THEN** 系统登记原任务重新分诊信号并由 Worker 处理，不复制任务；手动模式仍需选择，用户持久排除仍需明确重新启用

### Requirement: Issue 认领写入只按明确仓库授权执行

系统 SHALL 默认不修改 assignee、不发表评论；仓库显式开启认领评论后，仅由宿主受控发布器在准入通过、扫描就绪且即将实际修复时发布经配置的评论，持久化意图并去重、回执未知先读取对账。只读同步、Agent 与仓库工具不得自行评论或认领；该开关不授权自动索取信息或发布持续进度评论。

#### Scenario: 默认配置启动修复
- **WHEN** 合格 Issue 开始修复且仓库没有开启认领评论
- **THEN** 系统只取得本地占用，不调用 assignee 或评论写接口

#### Scenario: 认领评论成功但回执丢失
- **WHEN** 已授权的评论发布超时或 Worker 在写后中断
- **THEN** 系统核对持久意图和远端评论后确认结果，不因重启／重试重复发表评论；评论成功也不替代发布前占用／PR 核验

### Requirement: 同步失败和执行阻塞分别处理

系统 SHALL 对网络／限流等纯同步失败保留上次成功时间并退避，显示同步健康状态；只有任务必需权限或最新状态无法核验时才按执行障碍暂停全局队列。

#### Scenario: 一次定时读取被限流
- **WHEN** GitHub 返回限流或暂时网络错误
- **THEN** 系统按限制重试，不标记为没有变化，不自行调用模型或把所有任务标成失败

### Requirement: 重启只执行必要补偿同步

系统 SHALL 防止多个同步器并发领取同一仓库查询，将到期、人工和启动触发合并；重启只为已到期仓库执行一次补偿，不逐次重放停机期间所有定时点。

#### Scenario: 服务停机一天后启动
- **WHEN** 多个巡检时点已错过
- **THEN** 系统基于持久进度补偿同步并计算新的到期时间，不发起一串重复巡检
