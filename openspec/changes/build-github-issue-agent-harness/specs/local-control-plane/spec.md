# Spec Delta

## Purpose

为本地单用户提供持续运行服务的管理入口，使用户能够管理仓库、模型、任务、扫描、PR 和记忆，并在需要批准、排障或恢复时查看依据和执行明确操作，避免浏览器生命周期影响后台处理。

## ADDED Requirements

### Requirement: 后台服务独立于浏览器运行

系统 SHALL 在浏览器关闭后保留已启动的巡检与后台任务，并在重新打开界面时恢复展示持久化状态。

#### Scenario: 关闭并重新打开界面
- **WHEN** 用户关闭浏览器后再次访问运行中的本地服务
- **THEN** 系统展示原有任务与最新同步状态，不重复启动任务或重新导入仓库

### Requirement: 提供仓库和任务人工控制

系统 SHALL 支持多仓配置、目标分支选择、每仓库暂停、任务排除、优先级调整及全局暂停／显式恢复，操作结果具有持久标识。

#### Scenario: 暂停单个仓库
- **WHEN** 用户暂停仓库 A
- **THEN** 系统不再领取 A 的常规重任务，保留其只读同步，并允许其他满足条件的仓库继续执行

#### Scenario: 重复提交控制操作
- **WHEN** 界面重复提交同一操作标识且内容一致的请求
- **THEN** 系统返回原操作结果，不重复创建运行或重复解除暂停

#### Scenario: 相同操作标识携带不同内容
- **WHEN** 客户端复用操作标识却改变请求参数
- **THEN** 系统返回冲突，不执行新请求，也不把旧操作成功结果当作新内容已生效

#### Scenario: 本地候选 Issue 自动提交状态
- **WHEN** 用户选择一个本地扫描缺陷候选
- **THEN** 界面展示相似 Issue 查询、已关联 Issue 或系统创建 Issue 的操作状态；远端 Issue 确认前不展示修复分支已创建

#### Scenario: 等待外部 PR 决策
- **WHEN** 已关联 Issue 存在外部开放 PR 且关系不明确
- **THEN** 界面展示相关 PR、对照证据与等待原因，提供确认同一问题、确认无关、补充信息及取消入口；提交后重新核验，确认同一问题则关联等待，确认无关则继续原任务，不显示为正在自动修复

### Requirement: 每个人工介入节点都有可执行的 UI 入口

系统 SHALL 在待人工事项列表及相关仓库／扫描／任务／PR／系统详情提供可到达的处理入口，覆盖实施契约 §3 的全部人工介入类别。每项展示稳定标识、原因、关联对象及当前修订、证据、可执行操作、所需输入、前置条件和操作结果；暂不可执行的操作说明原因并链接补充入口。全局／仓库暂停期间人工管理仍可用，正常等待不强制增加人工批准。

#### Scenario: 相似 Issue 无法自动判定
- **WHEN** 系统无法确认候选与已有 Issue 是否为同一问题
- **THEN** 用户可在 UI 对照证据、选择关联已有 Issue 或确认不同问题并提交依据；系统重读核对，创建新 Issue 前仍须完成查重与回执核验

#### Scenario: Issue 或 PR 远端写入结果未知
- **WHEN** 创建／更新请求丢失回执或查询不完整
- **THEN** UI 展示操作意图、查询缺口及可能的远端对象，提供只读重新核对、提交待核验对象引用及 GitHub／权限配置入口；未核实前不重发写请求

#### Scenario: 方案或评审意见需要用户确认
- **WHEN** 方案待批准、评审意见有歧义或涉及范围／验收变化
- **THEN** UI 展示方案版本与差异，提供批准、要求修改、补充澄清及拒绝／取消入口；批准只覆盖所确认版本

#### Scenario: Issue 状态变化后任务有效性不明
- **WHEN** Issue 关闭、实质修改或重开后需用户确认当前范围
- **THEN** UI 展示输入差异和相关 PR，提供范围补充、重新分诊、取消／排除及适用的重新启用入口；重新核验当前 Issue，不按旧快照发布

#### Scenario: 扫描或 Bug 复现验证受阻
- **WHEN** 扫描存在无法补全的缺口，或任一来源的 Bug 无法复现、验证无法完成或归因
- **THEN** UI 展示覆盖或验证证据及日志，允许补充复现步骤、输入及环境说明，提供配置跳转、重试申请及取消；点击已处理不能替代覆盖或修改前后验证证据

#### Scenario: 配置缺失或预算不足
- **WHEN** 权限、环境、依赖、模型能力或预算障碍需要人工处理
- **THEN** UI 提供对应配置／修复指引、适用的有界诊断及预算调整入口，展示累计消耗；保存配置、调整预算或诊断通过不自动恢复常规队列或清零原账本

#### Scenario: 中断核对与全局恢复
- **WHEN** 任务执行中断、旧命令或远端副作用不明，或用户进入暂停处理页
- **THEN** UI 展示任务、检查点、产物、命令及远端核对报告和全部未解决原因，提供状态核对、遗留执行处理指引、相关事项跳转及显式恢复请求；未核实命令停止／隔离及全部适用条件前不恢复

#### Scenario: CI 维护者审批与合并在 GitHub 完成
- **WHEN** PR 等待 CI 授权、维护者评审、外部 PR 结果或合并
- **THEN** UI 展示当前提交对应状态，提供检查更新及 GitHub 检查／评审／合并页跳转，需要用户澄清时展示对应操作；不强制普通等待变成人工确认，也不自动合并

### Requirement: Issue 准入分诊与唯一交付可在 UI 管理

系统 SHALL 提供仓库三种准入模式、标签／严重程度映射、认领评论开关及模板预览；任务视图展示六类分诊结果、原因、证据、占用、待补充项及重新分诊条件，并展示 Issue／受管 PR 唯一绑定和外部观测。支持选择、补充信息、明确重新启用、请求接手／重新分诊、范围收敛／拆分方案确认及取消，所有提交受版本、权限、准入及交付门槛核验。

#### Scenario: 修改模式或选择 Issue
- **WHEN** 用户保存准入模式／映射或明确选择一个 Issue
- **THEN** 系统持久化策略修订及操作并展示生效范围和待分诊状态，不将保存动作当作模型分诊成功或绕过占用／复现；标签配置缺失有可操作入口

#### Scenario: 接手或敏感信息需确认
- **WHEN** 他人占用、输入矛盾或敏感披露方式导致不能自动推进
- **THEN** UI 展示脱敏依据及所需决定，允许澄清后请求重新分诊，不默认覆盖 assignee，也不因普通选择自动公开内容

#### Scenario: 查看一一对应交付关系
- **WHEN** 用户查看 Issue 或受管 PR，或尝试另建／批量关联交付
- **THEN** UI 明确展示唯一交付对象及外部 PR 观测，拒绝一对多／多对一的受管绑定；关闭后保留绑定，提供当前终态处理入口而不创建替代 PR

### Requirement: 人工决定持久化且不能绕过证据或恢复门槛

系统 SHALL 为人工提交保存操作标识、内容、预期对象修订、决定依据及结果，提交后重新核验当前输入／代码版本和适用的 Issue、PR、扫描、预算、执行权及证据条件；异步请求展示排队／等待恢复／运行／完成／失败及原因。普通确认不解除阻塞暂停，恢复须有明确意图并通过全部核验。涉及模型、仓库命令或发布的工作由受管任务／诊断执行，不能由 UI 请求绕过调度。

#### Scenario: 对过期 PR 版本提交关系判断
- **WHEN** 用户提交判断时 PR 或任务输入已实质变化
- **THEN** 系统返回版本冲突并展示最新依据供重新判断，不把旧决定应用于新版本

#### Scenario: 刷新或双击提交决定
- **WHEN** 已保存的决定被相同操作重复提交或页面重新加载
- **THEN** 系统回读原事项及操作结果，不重复创建 Issue、运行或恢复；无法持久化则明确失败，不声称决定已保存

#### Scenario: 处理一个原因后仍有其他阻塞
- **WHEN** 用户补充材料、取消任务或请求恢复，但还有未核实副作用、预算或验证条件
- **THEN** 系统保留全局暂停及剩余处理入口，不提供绕过门槛的强制通过结果

### Requirement: 提供手动检查仓库更新入口

系统 SHALL 在仓库界面提供“检查更新”，触发该仓库立即只读同步并检查目标分支，展示请求进度、最后成功时间、目标 SHA、无变化／发现变化／读取失败及关联扫描状态；该操作不增加导入代次或因同 SHA 触发全扫。

#### Scenario: 用户重复点击检查更新
- **WHEN** 相同操作重复提交或不同触发与正在执行的同步重叠
- **THEN** 相同操作返回原结果，触发在同步租约下合并；不能覆盖新请求的读取则安排后续读取，不重复建立活跃扫描

#### Scenario: 读取发现目标版本变化
- **WHEN** 检查确认目标分支 SHA 变化
- **THEN** 界面展示变化及前置扫描状态，扫描按既有预算和暂停规则排队，完成前不显示可自动修复

### Requirement: 提供无进展处理与预算续期操作

系统 SHALL 在任务详情和待人工事项展示无进展／振荡的触发窗口、尝试与失败签名、有效证据差异和处理入口；预算续期展示原授权、已用／预留、进度证据、剩余目标、继续策略、建议有限增量及估计不确定性，支持批准、修改有限额度、要求调整方案、拒绝／取消。明确区分预警、正常等待续期、预算耗尽阻塞和无进展阻塞，操作绑定版本并持久回读。

#### Scenario: 人工处理无进展
- **WHEN** 用户打开无进展或振荡事项
- **THEN** 可查看比较依据、补充输入／修改策略或环境、请求有界诊断／重试及取消，不能仅点已处理或加额就宣告恢复／验证通过

#### Scenario: 复杂任务请求有限续期
- **WHEN** 有进展的任务在耗尽前保存续期申请
- **THEN** UI 提供所需证据、剩余目标和各维有限额度表单，明确批准后的排队或仍暂停原因，不把正常续期展示为全局故障

#### Scenario: 追加预算时还有未处理阻塞
- **WHEN** 用户批准额度但全局／仓库暂停或无进展原因仍未解决
- **THEN** UI 显示已加额及新总额，同时保留阻塞及处理入口，不显示恢复成功或清空累计消耗

#### Scenario: 续期操作重复过期或估计不可靠
- **WHEN** 用户重复提交、提交旧申请，或估计缺少可靠依据
- **THEN** 相同有效操作只加额一次，旧申请返回冲突并刷新；未知估计标为待核实，允许填写有限额度，不展示虚构精确预算

### Requirement: 批准方案绑定明确验收条件

系统 SHALL 展示待批准方案、验收规范及其版本；功能、大规模重构或越过原范围的评审意见必须取得明确批准后才能实现。

#### Scenario: 方案未批准
- **WHEN** 功能请求已有方案但用户尚未批准
- **THEN** 任务正常等待并释放执行位，不开始代码修改

#### Scenario: 批准后方案内容变化
- **WHEN** 已批准方案的目标或验收条件发生实质变化
- **THEN** 旧批准不覆盖新版本，系统再次等待确认

### Requirement: 状态和证据可追踪展示

系统 SHALL 分别展示仓库就绪、扫描批次、任务、运行、PR 和全局状态，提供代码版本、覆盖缺口、预算消耗、阻塞原因及证据来源，不混用验证与交付结论。

#### Scenario: PR 关闭但未合并
- **WHEN** 受管 PR 被关闭且没有合并
- **THEN** 界面显示关闭未合并，不将其展示为 Issue 已解决

#### Scenario: 需要处理阻塞
- **WHEN** 任务因验证或环境障碍进入阻塞
- **THEN** 用户能够查看具体原因、已完成产物并执行对应的补充材料、配置、诊断、重试或恢复操作；操作受上述人工处理与恢复门槛约束

### Requirement: 事件和日志按范围访问

系统 SHALL 提供可恢复读取的任务事件和脱敏日志，用户重新连接时按已知位置补读，不因刷新触发实际模型或仓库执行。

#### Scenario: 界面连接中断
- **WHEN** 界面恢复连接并提供上次读取位置
- **THEN** 系统补充后续事件，并从业务状态重建视图，不启动新任务

### Requirement: 本地控制接口限制访问来源

系统 SHALL 默认只在回环地址提供控制接口，校验本地会话和变更请求来源，限制跨域来源，且不向客户端回显模型或 GitHub 密钥。

#### Scenario: 未授权来源尝试修改配置
- **WHEN** 无有效本地会话或来源不被允许的请求尝试修改配置、恢复队列或触发发布
- **THEN** 系统拒绝请求，不改变任务状态或产生远端写入

#### Scenario: 查看模型配置
- **WHEN** 用户读取已保存供应商配置或错误详情
- **THEN** 响应和日志仅显示脱敏信息，不返回可恢复的明文密钥
