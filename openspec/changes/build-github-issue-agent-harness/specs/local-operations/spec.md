# Spec Delta

## Purpose

使最终本地单用户系统能够安装、启动、停止、升级和恢复，在宿主、代码执行环境及持久数据之间保持一致的生命周期，并通过明确的首批适配样本和故障实验验证实际部署能力。

## ADDED Requirements

### Requirement: 本地启停管理服务和任务生命周期

系统 SHALL 提供管理 API 与 Worker 的启动／停止方式，停止时先停止领取任务，再确认命令结束或隔离、保存现场并记录有意挂起；异常退出进入人工恢复核对。

#### Scenario: 用户正常停止服务
- **WHEN** 有重任务正在执行
- **THEN** 系统不先释放其执行位再等待命令退出，重启后能够区分安全挂起与异常遗留

### Requirement: 数据库访问位于同一宿主环境

系统 SHALL 让 API、Worker 与默认本地数据库位于同一操作系统侧，任务执行环境不能通过共享路径跨 Windows／WSL 同时访问该数据库；持久业务状态与图进度分层保存。

#### Scenario: Windows 宿主使用 Linux 执行环境
- **WHEN** 任务在容器中执行
- **THEN** 业务数据库留在宿主且不挂入任务，宿主进程通过一致的本地路径访问

### Requirement: 升级迁移和备份具有一致性

系统 SHALL 由唯一迁移者在服务停止访问数据时校验并迁移版本；默认通过覆盖 API、同步、Worker、检查点、索引与清理写入的维护屏障取得一致备份和固定产物清单，恢复后核对工作区、远端状态及凭据引用，不将旧备份当作远端操作从未发生。

#### Scenario: 恢复创建 PR 之前的备份
- **WHEN** GitHub 上实际已有该任务 PR
- **THEN** 系统先对账并恢复关联，不因本地记录较旧而再次发布

#### Scenario: 数据库处于写入中
- **WHEN** 用户请求备份
- **THEN** 系统通过一致性接口或停写取得完整备份，不仅复制主文件而漏掉活动日志内容

#### Scenario: 备份期间同步器或清理器尝试写入
- **WHEN** 系统正在取得业务库、图状态及产物的统一备份
- **THEN** 相关写入和清理等待维护屏障释放，备份清单核验前不标记可恢复，结束后保留原有暂停原因

### Requirement: 存储故障停止执行和发布

系统 SHALL 自内核阶段起在业务状态或必要产物无法持久化时停止新执行和远端写入，记录可恢复原因；不能以仅存在内存结果继续交付，也不能将此保护推迟到最终运维界面完成。

#### Scenario: 发布前磁盘已满
- **WHEN** 系统不能可靠保存操作意图或证据
- **THEN** 系统停止发布并进入数据／环境障碍处理

### Requirement: 产物保留和清理保持引用准确

系统 SHALL 按用户配置保留工作区、日志及归档，保护未完成／阻塞任务引用内容；删除完成任务产物后标记其可用性，不再把缺失证据用于新验收。

#### Scenario: 清理完成任务的归档
- **WHEN** 保留策略允许删除旧产物
- **THEN** 系统同步更新引用状态，活动任务所需候选和证据不被自动删除

### Requirement: 首批适配和最终验收有明确证据

系统 SHALL 在 Windows 加默认执行环境上验证 Python 及 JavaScript／TypeScript 的 Web／CLI 样本，包括前端构建和必要浏览器验收；保留多语言适配边界，无法获得专用设备／私有服务时明确不支持或阻塞。

#### Scenario: 样本包含前后端应用
- **WHEN** 执行该项目的适配验收
- **THEN** 系统记录实际构建、运行及必要浏览器检查，不能仅因某个单元测试通过声称全链路可用

#### Scenario: 发布最终本地版本
- **WHEN** 计划完成 P0—P6
- **THEN** 验收提供模型协议、唯一执行位、扫描补全、修复证据、PR 对账、记忆与恢复实验的结果，未运行实验不得标为通过
