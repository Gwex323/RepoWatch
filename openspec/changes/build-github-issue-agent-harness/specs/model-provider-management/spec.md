# Spec Delta

## Purpose

让本地用户配置多个模型 API 供应商并按角色选择模型，以明确的能力检查和运行快照控制兼容性与消耗，同时保管凭据并保留用户对配置变化、诊断和恢复执行的控制权。

## ADDED Requirements

### Requirement: 供应商支持手工和指定 JSON 结构导入

系统 SHALL 支持手工新增／编辑及 JSON 文件／文本导入，接受单供应商、数组或 providers 包装；支持 name、base_url、api、api_key、models，以及模型的 model 和 reasoning_effort 字段。

#### Scenario: 导入包装数组
- **WHEN** 用户提供含 providers 数组的合法 JSON
- **THEN** 系统校验各项并展示导入结果，字段语义与既定参考项目一致

### Requirement: 批量导入只新增且整批原子保存

系统 SHALL 在整批校验及凭据准备成功后一次激活新供应商，不覆盖同名配置，任何无效、冲突或凭据保存失败都不得导致部分可用导入；跨凭据库与业务库中断须可对账，保存／导入不得自动请求模型或模型列表。

#### Scenario: 一项配置与已有名称冲突
- **WHEN** 批次包含同名供应商或无效条目
- **THEN** 系统拒绝本批次并指出条目，不保存其他条目或静默覆盖

#### Scenario: 保存合法供应商
- **WHEN** 用户仅保存配置而未请求测试或列表
- **THEN** 系统持久化配置且不产生供应商网络调用

#### Scenario: 凭据暂存后数据库提交失败
- **WHEN** 批量导入在跨存储激活前失败或进程中断
- **THEN** 系统不暴露半批配置，恢复时根据操作记录处理未激活凭据引用，不损坏旧配置或在日志保存密钥

### Requirement: 支持两类模型 API 和自定义地址

系统 SHALL 支持 chat_completions 与 responses 接口、自定义 base_url、模型列表拉取与手填模型；列表不可用不应阻止保存可手填的有效配置。

#### Scenario: 网关没有模型列表接口
- **WHEN** 用户显式拉取列表失败后手填模型名称
- **THEN** 系统保留配置，后续按真实角色能力验证，而不把列表失败等同于模型必然不兼容

### Requirement: 角色模型和运行快照独立配置

系统 SHALL 允许处理、独审及受管子任务选择不同供应商／模型和默认配置，在运行开始时固定配置快照，仅保存凭据引用及修订，不静默切换运行中配置。

#### Scenario: 运行期间修改默认模型
- **WHEN** 用户保存新的默认供应商或模型
- **THEN** 正在运行的任务继续使用原快照，新运行按明确选择解析配置

### Requirement: 必需能力通过真实角色检查准入

系统 SHALL 区分基础连接和角色就绪，在修复修改前核验处理与独审必需工具／结构化结果能力；结果按配置、凭据修订、模型、接口、工具适配版本及有效期约束。

#### Scenario: 连接成功但工具调用不可用
- **WHEN** 模型能返回文本但不能完成当前角色的工具和结果交接
- **THEN** 系统不判定角色就绪，任务进入能力阻塞而非跳过工具或独审

### Requirement: 失败有限重试且不自动跨供应商回退

系统 SHALL 对瞬时错误有限重试并计入原预算；持续错误、不兼容或额度／预算耗尽触发全局阻塞，不自动跨供应商切换或跳过验收。

#### Scenario: 供应商持续失败
- **WHEN** 既定重试无法恢复调用
- **THEN** 系统保留证据并暂停，等待用户调整配置及明确恢复

### Requirement: 凭据安全保存且诊断有界

系统 SHALL 使用宿主受保护凭据保存，不在配置读取、日志或 Agent 上下文回显密钥；用户显式请求的连接／能力测试有界执行，阻塞期间诊断不得自动恢复常规队列。

#### Scenario: 密钥已轮换或撤销
- **WHEN** 原运行凭据引用失效
- **THEN** 系统记录失败，用户明确选择新修订并恢复后才建立新运行快照
