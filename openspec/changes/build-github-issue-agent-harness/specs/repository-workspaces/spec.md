# Spec Delta

## Purpose

为多个 GitHub 仓库提供受管导入、代码快照和隔离执行环境，保留用户日常目录中的分支与未提交内容，并使验证、审查和发布针对同一可追踪代码版本，按贡献路径控制权限。

## ADDED Requirements

### Requirement: 支持受权仓库与第三方公共贡献路径

系统 SHALL 支持有维护权限的公共／私有仓库，以及允许 Fork 的第三方公共仓库；保存上游与发布仓库身份、目标分支及授权引用，并核验实际贡献路径。

#### Scenario: 导入第三方公共仓库
- **WHEN** 用户选择通过自己的 Fork 向上游贡献
- **THEN** 系统分别记录并检查上游读取、Fork 写入和上游 PR 路径，不以能写 Fork 代替全部权限检查

#### Scenario: 执行需要的权限不足
- **WHEN** 任务无法取得实际读取或交付权限
- **THEN** 系统记录执行障碍并按全局阻塞规则处理，不猜测或提升权限

#### Scenario: 重复登记同一远端仓库
- **WHEN** 新导入请求解析到已有 GitHub 稳定仓库 ID
- **THEN** 系统复用仓库身份并建立新导入扫描，不复制 Issue 主任务、PR 关联或记忆范围

#### Scenario: 用户改变目标分支
- **WHEN** 已有任务或 PR 的仓库目标配置发生变化
- **THEN** 系统撤销旧就绪，新任务使用新配置，已有任务／PR 保留原快照并等待明确处理，不自动改投

### Requirement: 保留用户日常工作目录

系统 SHALL 在独立受管副本执行扫描和修复，不修改用户日常目录的当前分支、未提交内容或未跟踪文件。

#### Scenario: 用户目录有未提交改动
- **WHEN** 系统为同一仓库建立修复运行
- **THEN** 运行使用受管代码副本，用户原目录内容和分支保持原状

### Requirement: 代码物化保持可核对内容

系统 SHALL 固定代码提交并记录实际物化内容，正确处理换行、大小写、可执行位、符号链接、自有子模块及 LFS 内容；必要内容无法取得时不得伪称已检查。

#### Scenario: 仓库包含 LFS 指针或自有子模块
- **WHEN** 约定受检内容尚未被完整物化
- **THEN** 系统显示缺口，补齐后才允许将其计为扫描覆盖或验证输入

#### Scenario: Git bundle 缺少外部内容
- **WHEN** bundle 已传递但 LFS 实体或子模块对象尚不可得
- **THEN** 系统按独立物化清单识别缺口，不把 Git 对象交接成功当作所有内容已经取得

#### Scenario: 符号链接指向工作区外
- **WHEN** 文件工具遇到越界链接
- **THEN** 系统不越界读取或写入，并记录该内容的处理结果

### Requirement: 按任务模式限制工作区能力

系统 SHALL 默认在受管 Linux 容器执行仓库命令；处理模式仅写当前任务工作区，扫描和独审模式只读受检代码，构建／检查写入使用受管临时副本，原生执行必须显式启用。

#### Scenario: 审查角色尝试修改代码
- **WHEN** 独审请求可写文件或通用可写终端
- **THEN** 系统拒绝能力请求；必要检查交由受控执行器在临时副本完成

#### Scenario: 需要宿主专用能力
- **WHEN** 项目无法在默认环境完成验证
- **THEN** 系统要求显式启用符合边界的原生适配，否则保持不支持或阻塞状态

### Requirement: 仓库执行无法取得宿主凭据与控制能力

系统 SHALL 将模型和 GitHub 写凭据保留在宿主受控适配层，不通过仓库配置、日志、通用容器、控制接口或宿主挂载暴露；持写凭据时不得运行仓库脚本或不受控 Git hooks／过滤器。

#### Scenario: 私有仓库执行测试
- **WHEN** 代码由宿主凭据获取后进入任务环境
- **THEN** 环境不包含令牌、宿主凭据库、业务数据库或宿主容器控制接口

#### Scenario: 仓库定义发布相关 hook
- **WHEN** 发布器处理候选 Git 对象
- **THEN** 仓库 hook 或过滤器不能在持有 GitHub 写凭据的环境执行
